## 1. 客户端身份标识体系

### 1.1 持久设备 ID（最核心的追踪标识）

**文件**: `src/utils/config.ts` → `getOrCreateUserID()`

```typescript
export function getOrCreateUserID(): string {
  const config = getGlobalConfig()
  if (config.userID) return config.userID

  const userID = randomBytes(32).toString('hex')  // 64 hex chars
  saveGlobalConfig(current => ({ ...current, userID }))
  return userID
}
```

| 属性 | 值 |
|------|-----|
| 格式 | 64 位十六进制字符串（32 字节随机数） |
| 存储位置 | `~/.claude/config.json` 的 `userID` 字段 |
| 生命周期 | **永久**，除非手动删除该文件 |
| 传输方式 | 每个 API 请求 body 的 `metadata.user_id.device_id` |
| 传输方式 | 每个遥测事件的 `device_id` 字段 |
| 传输方式 | GrowthBook 用户属性的 `id` / `deviceID` |

**风控意义**: 这是 Anthropic 识别"一台机器"的唯一持久标识。同一个 device_id 频繁更换账号 = 异常。多个 device_id 使用同一个账号 = 共享账号。


| 属性 | 值 |
|------|-----|

### 2.4 消息指纹算法

**文件**: `src/utils/fingerprint.ts`

```typescript
export const FINGERPRINT_SALT = '59cf53e54c78'  // 硬编码盐值，必须匹配后端

export function computeFingerprint(messageText: string, version: string): string {
  const indices = [4, 7, 20]
  const chars = indices.map(i => messageText[i] || '0').join('')
  const fingerprintInput = `${FINGERPRINT_SALT}${chars}${version}`
  const hash = createHash('sha256').update(fingerprintInput).digest('hex')
  return hash.slice(0, 3)  // 3 字符 hex
}
```

**计算过程**:
1. 取用户第一条消息的第 4、7、20 个字符（不存在则用 "0"）
2. 拼接：`59cf53e54c78` + 三字符 + 版本号
3. SHA256 哈希，取前 3 位 hex

**风控意义**: 服务端收到请求后，可以用同样算法验证指纹是否与实际消息内容一致。如果不一致 = 消息被篡改或中间人攻击。

### 5.6 重试策略

**文件**: `src/services/api/withRetry.ts`

| 错误码 | 重试策略 | 特殊行为 |
|--------|----------|----------|
| 429 | API Key 用户重试; Max/Pro 不重试 | 尊重 Retry-After |
| 529 | 最多 3 次 → 降级模型 | 后台查询直接丢弃 |
| 401/403 | 刷新凭证后重试 | Bedrock/Vertex 刷新 AWS/GCP 凭证 |
| 408/409 | 自动重试 | — |

```typescript
  if (isRateLimitError(error)) return 'rate_limit'
  if (error.status === 429) return 'rate_limit'
```

## 7. 客户端认证签名机制 (cch)

### 7.1 实现原理

**文件**: `src/constants/system.ts:59-95`

```typescript
// 1. JS 层面插入占位符
const cch = feature('NATIVE_CLIENT_ATTESTATION') ? ' cch=00000;' : ''

// 2. 占位符被嵌入到请求 body 的 system prompt 中
const header = `x-anthropic-billing-header: cc_version=${version}; cc_entrypoint=${entrypoint};${cch}`
```

### 7.2 签名流程

```
┌─────────────────────────────────────────────────────┐
│  JS 层                                               │
│  构造请求 body，包含 "cch=00000" 占位符               │
└───────────────────────┬─────────────────────────────┘
                        │ 请求序列化
                        ▼
┌─────────────────────────────────────────────────────┐
│  Bun 原生 HTTP 层 (Attestation.zig)                  │
│  1. 在序列化后的字节流中找到 "cch=00000"              │
│  2. 计算请求内容的加密哈希                            │
│  3. 原地覆写 5 个零为 5 字符哈希                      │
│  4. 不改变 Content-Length（同长度替换）               │
└───────────────────────┬─────────────────────────────┘
                        │ 发送到服务端
                        ▼
┌─────────────────────────────────────────────────────┐
│  Anthropic 服务端                                    │
│  1. 解析 cch 值                                      │
│  2. 用同样算法验证哈希是否匹配请求内容                │
│  3. 不匹配 → 非法客户端/篡改请求                     │
└─────────────────────────────────────────────────────┘
```

### 7.3 风控意义

- 在 Bun 的 **Zig 原生代码** 中实现，JS 层面无法拦截或修改
- 如果你用修改过的客户端、代理转发、或非 Bun 运行时，**签名将不匹配**
- 服务端可以据此判断请求是否来自正版 Claude Code
- 占位符的 "同长度替换" 设计避免了 Content-Length 重计算

### 7.4 禁用方式

```bash
# 环境变量禁用归因 Header（整个 header 消失，包括 cch）
CLAUDE_CODE_ATTRIBUTION_HEADER=false

# GrowthBook 远程禁用
tengu_attribution_header = false
```

**注意**: 禁用归因 Header 可能本身就是一个异常信号。

## 14. 遥测禁用与规避分析

### 14.1 可禁用的部分

| 环境变量 | 禁用效果 |
|----------|----------|
| `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` | 禁用全部非必要网络请求（遥测、更新、GrowthBook） |
| `CLAUDE_CODE_ANALYTICS_DISABLED=1` | 禁用分析 |
| `DISABLE_TELEMETRY=1` | 禁用遥测 |
| `CLAUDE_CODE_ATTRIBUTION_HEADER=false` | 禁用归因 Header |

### 14.2 无法禁用的部分

以下内容 **无论如何设置环境变量都会发送**：

| 数据 | 位置 | 原因 |
|------|------|------|
| `metadata.user_id` (device_id + account_uuid) | API 请求 body | 嵌入请求体，非 Header |
| 对话内容 | `/v1/messages` body | 这就是 API 调用本身 |
| session_ingress 会话记录 | `PUT /v1/session_ingress/...` | 远程会话功能需要 |
| OAuth Token 刷新 | `POST /v1/oauth/token` | 认证必需 |
| Rate limit headers | API 响应 | 服务端返回的，客户端被动接收 |

### 14.3 规避分析

即使禁用了三条遥测管道，Anthropic 服务端仍然可以从 **API 请求本身** 获取：

1. **device_id** — 从 `metadata.user_id.device_id` 获取
2. **account_uuid** — 从 `metadata.user_id.account_uuid` 获取
3. **session_id** — 从 `metadata.user_id.session_id` 获取
4. **cch 签名** — 从请求 body 获取
5. **消息指纹** — 从 `cc_version` 的后 3 字符获取
6. **使用模式** — 从请求频率、token 消耗、模型选择推断
7. **对话内容** — 从 messages 数组获取
8. **IP 地址** — TCP 连接层面
