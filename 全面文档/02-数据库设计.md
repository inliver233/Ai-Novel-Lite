## 1. 数据库类型与配置

### 支持的数据库

本系统同时支持 **SQLite** 和 **PostgreSQL** 两种数据库后端，通过配置项 `DATABASE_URL` 自动识别。

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `database_url` | `sqlite:///./ainovel.db` | 数据库连接字符串 |
| `db_pool_size` | `5` | 连接池大小（仅 PostgreSQL） |
| `db_max_overflow` | `10` | 最大溢出连接数（仅 PostgreSQL） |
| `db_pool_timeout_seconds` | `30` | 连接池等待超时秒数（仅 PostgreSQL） |
| `db_pool_recycle_seconds` | `1800` | 连接回收周期秒数（仅 PostgreSQL） |

### SQLite 特殊配置

当使用 SQLite 时，引擎连接时自动设置以下 PRAGMA：

| PRAGMA | 值 | 作用 |
|--------|------|------|
| `foreign_keys` | `ON` | 启用外键约束 |
| `journal_mode` | `WAL` | 使用 Write-Ahead Logging 模式，提升并发读写性能 |
| `synchronous` | `NORMAL` | 在 WAL 模式下的推荐同步级别，平衡安全和性能 |
| `busy_timeout` | `5000` | 繁忙等待超时（毫秒），避免 SQLITE_BUSY 错误 |

同时，SQLite 连接参数中设置 `check_same_thread=False`，允许跨线程使用同一连接。

**源码位置**: `backend/app/db/session.py`，`backend/app/core/config.py`

## 2. 数据库连接与会话管理

### ORM 基类

```
文件: backend/app/db/base.py
```

使用 SQLAlchemy 2.0 的 `DeclarativeBase` 作为所有模型的基类。所有 ORM 模型均继承自 `Base` 类。

### 引擎与会话工厂

```
文件: backend/app/db/session.py
```

- **引擎创建**: 通过 `create_engine()` 创建，启用 `pool_pre_ping=True`（每次从连接池获取连接前先 ping 验活）
- **PostgreSQL 连接池**: 配置 `pool_size`、`max_overflow`、`pool_timeout`、`pool_recycle` 四个参数
- **SQLite 连接池**: 不使用连接池配置（SQLite 的连接本身是文件级别的）
- **会话工厂**: `SessionLocal = sessionmaker(bind=engine, autoflush=False, expire_on_commit=False)`
  - `autoflush=False`: 不自动刷新，由应用手动控制
  - `expire_on_commit=False`: 提交后不过期属性，避免延迟加载问题

### 依赖注入

```python
def get_db() -> Generator[Session, None, None]:
```

以生成器方式提供数据库会话，作为 FastAPI 的依赖注入使用。会话在使用完毕后自动关闭。

## 3. 时间处理兼容性机制

```
文件: backend/app/db/datetime_compat.py
```

由于 SQLite 不原生支持带时区的 `DateTime` 类型，本系统实现了全局时间标准化机制：

### 核心函数

| 函数 | 作用 |
|------|------|
| `coerce_utc_datetime(value)` | 将任意时间值（字符串或 datetime）转换为 UTC 时区的 datetime 对象。支持解析 ISO 格式字符串（含 `Z` 后缀），无时区信息时默认视为 UTC |
| `utc_datetime_iso(value)` | 将时间值转换为 ISO 格式字符串，`+00:00` 替换为 `Z` |
| `normalize_instance_datetime_fields(instance)` | 对 ORM 实例中所有 `DateTime` 类型字段执行 UTC 标准化。仅在 SQLite 模式下生效 |

### 自动标准化事件监听

通过 SQLAlchemy 事件系统，在 `Base` 类上注册了两个全局监听器：

- **`load` 事件**: ORM 实例从数据库加载时，自动标准化所有 DateTime 字段
- **`refresh` 事件**: ORM 实例刷新时，仅标准化被刷新的 DateTime 字段

这确保了从 SQLite 中读取的时间值始终带有正确的 UTC 时区信息。

## 4. 数据库工具函数

```
文件: backend/app/db/utils.py
```

| 函数 | 返回类型 | 作用 |
|------|----------|------|
| `new_id()` | `str` | 生成 UUID4 字符串，作为各表的主键 |
| `utc_now()` | `datetime` | 获取当前 UTC 时间，精度截断到秒（`microsecond=0`） |
| `utc_now_iso()` | `str` | 获取当前 UTC 时间的 ISO 字符串表示，`+00:00` 替换为 `Z` |

`utc_now` 被广泛用于所有模型的 `created_at`、`updated_at` 字段的 `default` 和 `onupdate` 回调。

## 5. 数据库迁移机制（Alembic）

### 配置文件

```
文件: backend/alembic.ini
```

- **脚本目录**: `alembic/`
- **默认数据库 URL**: `sqlite:///./ainovel.db`（可被环境变量 `DATABASE_URL` 覆盖）

### 迁移环境

```
文件: backend/alembic/env.py
```

- 自动加载 `.env` 文件中的环境变量
- 导入 `Base.metadata` 作为目标元数据（`target_metadata`），使 Alembic 能自动检测模型变更
- 通过 `import app.models` 确保所有 ORM 模型被注册到 metadata
- 支持离线和在线两种迁移模式
- SQLite 模式下启用 `render_as_batch=True`（批处理模式），因为 SQLite 不支持 ALTER TABLE 的部分操作
- 启用 `compare_type=True`（类型比较），确保字段类型变更也能被检测

### 自动升级机制

```
文件: backend/app/db/migrations.py
```

`ensure_db_schema()` 函数在应用启动时自动调用，确保数据库 schema 处于最新状态：

1. **空数据库**: 直接执行 `alembic upgrade head` 创建所有表
2. **旧数据库**: 自动升级到最新版本
3. **遗留 SQLite（无 alembic_version 表）**: 尝试安全 stamp 后再升级
   - 检测是否已有新 schema（`outlines`、`llm_profiles` 表和相关字段），判断 stamp 目标版本
   - 生产环境（`APP_ENV=prod`）下**禁止**自动 stamp，需要手动操作
4. **PostgreSQL 并发保护**: 使用 `pg_advisory_lock` 防止多实例同时执行迁移
   - 锁 ID 默认 `8260228`，可通过 `DB_MIGRATION_LOCK_ID` 环境变量配置
   - 超时默认 60 秒，通过 `DB_MIGRATION_LOCK_TIMEOUT_SECONDS` 配置
   - 轮询间隔默认 0.2 秒，通过 `DB_MIGRATION_LOCK_POLL_SECONDS` 配置

| `updated_at` | DateTime(tz) | NOT NULL | utc_now | 更新时间（自动更新） |

**索引**: 无额外索引（email 已有 UNIQUE 约束隐含索引）

**外键关系**: 无（被大量其他表引用）
