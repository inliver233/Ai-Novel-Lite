# 07 - 后端服务层：大纲生成

## 一、大纲生成完整流程概览

大纲生成是 AI 小说写作平台中用于自动生成小说章节大纲的核心功能。系统支持单次生成和分段生成两种模式，并具备多层次的缺失章节修复机制。

```
用户请求
  |
  v
outline_generation_app_service (入口编排)
  |
  +---> prepare_outline_generation (准备阶段)
  |       |
  |       +---> 权限验证 (require_project_editor)
  |       +---> LLM配置解析 (resolve_task_llm_config)
  |       +---> 风格解析 (resolve_style_guide)
  |       +---> 角色加载 (format_characters)
  |       +---> 目标章数提取 + 指导规则构建
  |       +---> 提示词渲染 (render_preset_for_task)
  |       +---> max_tokens 自动推荐
  |
  +---> 路由决策: 是否启用分段模式？
  |
  +---> [分段模式] _generate_outline_segmented_with_llm
  |       |
  |       +---> 批次划分 (_outline_segment_batches)
  |       +---> 逐批 LLM 调用
  |       +---> 章节合并 (_merge_segment_chapters)
  |       +---> 章节覆盖检查 (_enforce_outline_chapter_coverage)
  |       +---> 缺失章节填充 (_fill_outline_missing_chapters_with_llm)
  |       |       +---> 间隙修复 (_repair_outline_remaining_gaps_with_llm)
  |       |       |       +---> 最终扫描修复 (_repair_outline_remaining_gaps_final_sweep_with_llm)
  |       +---> 写入聚合运行记录
  |
  +---> [单次模式] call_llm_and_record
  |       |
  |       +---> 输出解析 (contract_for_task("outline_generate").parse)
  |       +---> [可选] JSON 修复 (build_repair_prompt_for_task)
  |       +---> 章节覆盖检查
  |       +---> 缺失章节填充
  |
  v
返回结果 / SSE 流式输出
```

### 多层修复机制

大纲生成的一个核心设计是多层次的章节完整性修复：

```
第1层: _fill_outline_missing_chapters_with_llm    (主填充)
  |
  +---> 如果仍有缺失
        |
        v
第2层: _repair_outline_remaining_gaps_with_llm    (间隙修复)
  |
  +---> 如果仍有缺失
        |
        v
第3层: _repair_outline_remaining_gaps_final_sweep_with_llm (最终扫描)
        |
        +---> 逐章逐个修复
```

## 二、应用服务层 (outline_generation_app_service.py)

**文件路径**: `backend/app/services/outline_generation_app_service.py`

此文件是大纲生成的顶层入口，负责编排完整流程。

### 2.1 generate_outline 方法 (核心入口)

**功能**: 非流式大纲生成的完整入口。

**参数**:
- `request_id`: 请求唯一标识
- `project_id`: 项目 ID
- `body`: `OutlineGenerateRequest` 请求体
- `user_id`: 用户 ID
- `x_llm_provider` / `x_llm_api_key`: 可选的 LLM 提供商和密钥

**完整流程**:

#### 阶段一：准备
1. 获取 `outline_route` 对象（延迟导入路由层的功能方法）
2. 调用 `prepare_outline_generation` 准备所有参数

#### 阶段二：路由分支

**分段模式** (当 `_should_use_outline_segmented_mode` 返回 True):
1. 调用 `_generate_outline_segmented_with_llm` 执行分段生成
2. 调用 `_write_outline_segmented_aggregate_run` 写入聚合运行记录
3. 组装返回数据:
   - 去重 warnings
   - 设置 generation_run_id (聚合)
   - 设置 generation_sub_run_ids 和 generation_run_ids (含所有子运行)
   - 设置 latency_ms、dropped_params、finish_reason(s)
   - 设置 segmented_generation 元信息

**单次模式**:
1. 调用 `call_llm_and_record` 执行 LLM 调用 (run_type="outline")
2. 使用 `contract_for_task("outline_generate")` 解析输出
3. **JSON 修复**（仅 OpenAI 系列提供商）:
   - 如果解析失败，调用 `build_repair_prompt_for_task` 构建修复提示词
   - 使用 temperature=0, max_tokens=1024 调用修复 LLM
   - 如果修复成功，替换数据并添加 "json_fixed_via_llm" 警告
4. **章节覆盖检查**: `_enforce_outline_chapter_coverage`
5. **缺失章节填充**: `_fill_outline_missing_chapters_with_llm`

#### 阶段三：结果组装
- 去重 warnings
- 设置 generation_run_id、latency_ms、dropped_params、finish_reason

### 2.2 prepare_outline_stream_request 方法

**功能**: 流式大纲生成的请求准备入口，直接委托给 `prepare_outline_generation`。

## 三、准备阶段 (outline_generation_prepare_service.py)

**文件路径**: `backend/app/services/outline_generation_prepare_service.py`

### 3.1 prepare_outline_generation 方法

**功能**: 完整的大纲生成请求准备流程，返回 `PreparedOutlineGeneration`。

**详细流程**:

1. **权限验证**: `require_project_editor` 验证用户对项目的编辑权限

2. **LLM 配置解析**:
   - 调用 `resolve_task_llm_config` (task_key="outline_generate")
   - 验证 API 密钥存在且提供商一致

3. **项目设置加载**:
   - 获取 world_setting、style_guide、constraints
   - 根据 `body.context.include_world_setting` 决定是否包含这些设置

4. **风格解析**: 如果包含世界设置，调用 `resolve_style_guide`

5. **角色加载**: 如果 `body.context.include_characters` 为 True，查询所有角色并格式化

6. **目标章数与指导规则**:
   - 调用 `_extract_target_chapter_count` 从 requirements 提取目标章数
   - 调用 `_build_outline_generation_guidance` 构建章数规则和详情规则

7. **构建渲染值字典**:
   - 项目信息: project_name, genre, logline
   - 设置信息: world_setting, style_guide, constraints
   - 角色信息: characters
   - 需求信息: requirements (JSON 格式)
   - 目标章数: target_chapter_count
   - 指导规则: chapter_count_rule, chapter_detail_rule
   - 空占位: outline, chapter_number, chapter_title, chapter_plan, instruction, previous_chapter

8. **提示词渲染**: 调用 `render_preset_for_task` (task="outline_generate")

9. **max_tokens 自动推荐**:
   - 调用 `_recommend_outline_max_tokens` 根据目标章数推荐合适的 max_tokens
   - 如果推荐值有效，覆盖 LLM 调用参数
   - 记录 `outline_auto_max_tokens` 到运行参数

10. **构建运行参数 JSON**

### 3.2 _build_outline_segment_aggregate_output_text 方法

**功能**: 构建分段生成的聚合输出文本。

**内容**:
- 模式: "segmented"
- 章节数
- 前 40 条 warnings
- 分段生成元信息
- 章节覆盖摘要（如果有）

### 3.3 _write_outline_segmented_aggregate_run 方法

**功能**: 写入分段生成的聚合运行记录。

**流程**:
1. 构建聚合输出文本
2. 如果有 parse_error，构建错误 JSON
3. 调用 `write_generation_run` 写入记录 (run_type 由调用方指定，如 "outline_segmented" 或 "outline_stream_segmented")

## 四、分段服务 (outline_generation_segment_service.py)

**文件路径**: `backend/app/services/outline_generation_segment_service.py`

### 4.1 _generate_outline_segmented_with_llm 方法

**功能**: 分段模式的核心实现，将大量章节拆分为多个批次逐步生成。

**参数**:
- request_id, actor_user_id, project_id: 标识信息
- api_key: LLM API 密钥
- llm_call: LLM 调用配置
- prompt_system / prompt_user: 基础提示词
- target_chapter_count: 目标章数
- run_params_extra_json: 额外运行参数
- progress_hook: 进度回调（可选）

**完整流程**:

#### 4.1.1 初始化
- 计算批次大小: `_outline_segment_batch_size_for_target`
- 划分批次: `_outline_segment_batches`
- 初始化章节映射表 `chapters_by_number`

#### 4.1.2 批次循环

对每个批次:

1. **计算缺失章节**: 过滤已有章节
2. **重试循环**: 每个批次最多 `_outline_segment_max_attempts_for_batch` 次尝试

每次尝试:

3. **发送进度**: `segment_start`、`batch_attempt_start`
4. **构建分段提示词**: `_build_outline_segment_prompts`，传入已有章节和已有大纲文本
5. **调整 max_tokens**: `_recommend_outline_segment_max_tokens`
6. **LLM 调用**: 调用 `call_llm_and_record` (run_type="outline_segment")
7. **解析输出**: `_parse_outline_batch_output`

**结果处理**:
- **调用失败**: 添加警告，累计 stagnant_attempts
- **解析失败**: 添加警告，累计 stagnant_attempts
- **无进展**: 分析原因（章号不匹配/重复旧章节/未输出可识别章节），累计 stagnant_attempts
- **成功**: 合并章节 (`_merge_segment_chapters`)，重置 stagnant_attempts

**停滞限制**: 任何批次连续停滞达到 `OUTLINE_SEGMENT_STAGNANT_ATTEMPTS_LIMIT` 次则跳出

#### 4.1.3 后处理

1. **大纲文本回退**: 如果没有 outline_md，生成默认文本
2. **章节覆盖检查**: `_enforce_outline_chapter_coverage`
3. **缺失章节填充**: `_fill_outline_missing_chapters_with_llm`（带进度回调转发）
4. **构建元信息**: mode, target_chapter_count, batch_size, batch_count, run_count
5. **返回 `OutlineSegmentGenerationResult`**

## 五、填充服务 (outline_generation_fill_service.py)

**文件路径**: `backend/app/services/outline_generation_fill_service.py`

### 5.1 _fill_outline_missing_chapters_with_llm 方法

**功能**: 填充大纲中缺失的章节，是多层修复机制的第一层。

**参数**: data, target_chapter_count, request_id, actor_user_id, project_id, api_key, llm_call, run_params_extra_json, progress_hook

**流程**:

#### 5.1.1 前置检查
- 如果 target_chapter_count 无效，直接返回
- 标准化现有章节 (`_normalize_outline_chapters`)
- 收集缺失章节号 (`_collect_missing_chapter_numbers`)
- 计算最大尝试次数 (`_outline_fill_max_attempts_for_missing`)

#### 5.1.2 填充循环

每次迭代:

1. **重新收集缺失**: 每次循环开始时重新计算
2. **批次选取**: `_outline_fill_batch_size_for_missing` 确定当前批次大小
3. **构建填充提示词**: `_build_outline_missing_chapters_prompts`
4. **调整 max_tokens**: `_recommend_outline_max_tokens`
5. **LLM 调用**: run_type="outline_fill_missing"
6. **解析结果**: 使用 `outline_generate` 合约解析

**结果处理**:
- **调用失败**: 累计 stagnant_rounds
- **解析失败**: 累计 stagnant_rounds
- **输出为空**: 累计 stagnant_rounds
- **无进展**: 累计 stagnant_rounds
- **成功**: 合并新章节到 by_number 映射，重置 stagnant_rounds

**章节评分**: 使用 `_chapter_score` 比较新旧章节质量，仅在新章节评分更高时替换。

**停滞限制**: `OUTLINE_FILL_STAGNANT_ROUNDS_LIMIT`

#### 5.1.3 后续修复

1. **章节覆盖检查**: `_enforce_outline_chapter_coverage`
2. **如果仍有缺失**: 调用第二层修复 `_repair_outline_remaining_gaps_with_llm`
3. **更新覆盖信息**: 记录 gap_repair_run_ids
4. **最终状态检查**: 如果仍有缺失，添加 "outline_fill_missing_remaining" 警告

## 六、间隙修复服务 (outline_generation_gap_repair_service.py)

**文件路径**: `backend/app/services/outline_generation_gap_repair_service.py`

### 6.1 _repair_outline_remaining_gaps_with_llm 方法

**功能**: 第二层修复，针对填充后仍然缺失的章节进行修复。

**前置条件**:
- target_chapter_count 有效
- 存在缺失章节
- 缺失数量不超过 `OUTLINE_GAP_REPAIR_MAX_MISSING`

**流程**:

#### 6.1.1 修复循环

与填充服务类似的重试循环:

1. **批次选取**: 每次取 `OUTLINE_GAP_REPAIR_BATCH_SIZE` 个缺失章节
2. **构建修复提示词**: `_build_outline_gap_repair_prompts`，包含:
   - 目标章数和批次缺失章号
   - 已有章节作为上下文
   - 当前大纲文本
   - 前次失败原因和输出章号（用于引导 LLM 纠正）
3. **调整 max_tokens**: `_recommend_outline_segment_max_tokens`
4. **LLM 调用**: run_type="outline_gap_repair"
5. **解析与合并**: 同填充服务逻辑

**停滞限制**: `OUTLINE_GAP_REPAIR_STAGNANT_LIMIT`

#### 6.1.2 后续处理

1. 章节覆盖检查
2. 如果仍有缺失，调用第三层修复: `_repair_outline_remaining_gaps_final_sweep_with_llm`
3. 再次检查覆盖
4. 添加最终状态警告:
   - "outline_gap_repair_final_sweep_remaining": 仍有缺失
   - "outline_gap_repair_final_sweep_resolved" + "outline_gap_repair_resolved": 全部修复
   - "outline_gap_repair_resolved": 无需最终扫描即已修复

## 七、最终扫描修复服务 (outline_generation_gap_repair_final_sweep_service.py)

**文件路径**: `backend/app/services/outline_generation_gap_repair_final_sweep_service.py`

### 7.1 _repair_outline_remaining_gaps_final_sweep_with_llm 方法

**功能**: 第三层（最终）修复，逐章逐个尝试修复剩余缺失。

**前置条件**:
- 缺失数量不超过 `OUTLINE_GAP_REPAIR_FINAL_SWEEP_MAX_MISSING`

**与前两层的区别**:
- **逐章处理**: 外循环遍历每个缺失章号，内循环对每章最多尝试 `OUTLINE_GAP_REPAIR_FINAL_SWEEP_ATTEMPTS_PER_CHAPTER` 次
- **更精准**: 每次只请求一个章号 (`batch_missing=[number]`)
- **独立重试**: 每章的失败不影响其他章的修复

**流程**:

对每个缺失章号:
1. 构建修复提示词（同间隙修复，但 batch_missing 仅含一个章号）
2. 调整 max_tokens（requested_count=1）
3. LLM 调用 (run_type="outline_gap_repair_final_sweep")
4. 解析输出
5. 严格匹配: 只接受章号与目标一致的输出
6. 如果成功修复，标记 `chapter_fixed = True` 并跳出内循环
7. 如果所有尝试都失败，添加 "outline_gap_repair_final_sweep_chapter_unresolved" 警告

## 八、流式服务 (outline_generation_stream_service.py)

**文件路径**: `backend/app/services/outline_generation_stream_service.py`

### 8.1 generate_outline_stream_events 方法

**功能**: SSE 流式大纲生成的核心生成器函数。

**完整流程**:

#### 8.1.1 初始化
- 发送初始进度 (0%)
- 提取准备好的参数

#### 8.1.2 分段模式分支

**触发条件**: `_should_use_outline_segmented_mode` 返回 True

**流程**:
1. 发送进度 "长篇模式：分段生成中..." (10%)
2. 使用线程安全的进度事件收集器 (`segment_progress_lock` + `segment_progress_events`)
3. 在 `ThreadPoolExecutor` 中启动分段生成 (`_generate_outline_segmented_with_llm`)
4. 主线程轮询进度事件，通过 `iter_segment_progress_sse_events` 转化为 SSE 事件:
   - 心跳事件
   - 进度消息
   - 章节快照（在 batch_applied 等事件时发送 `sse_result`）
   - 原始输出预览（通过 `sse_chunk` 发送）
5. 获取分段结果
6. 写入聚合运行记录
7. 调用 `finalize_segmented_outline_stream_result` 整理结果
8. 发送完成 (100%)

#### 8.1.3 单次模式分支

**流程**:
1. 发送进度 "调用模型..." (10%)
2. **流式 LLM 调用**: `call_llm_stream_messages`
   - 逐块读取 delta，发送 `sse_chunk`
   - 每 12 个 chunk 发送一次心跳
   - 每 0.8 秒更新一次进度（基于 6000 字符估算）
3. 记录日志和运行记录 (run_type="outline_stream")
4. **输出解析** (90%): 使用 outline_generate 合约
5. **JSON 修复** (92%): 仅 OpenAI 系列提供商
6. **章节覆盖检查**:
   - 发送预览结果 (`sse_result` 带当前章节数据)
7. **缺失章节填充** (94%):
   - 在 `ThreadPoolExecutor` 中启动填充
   - 主线程通过 `iter_fill_progress_sse_events` 轮询并发送进度事件
   - 每次填充应用时发送章节快照
8. 调用 `finalize_outline_stream_result` 整理结果
9. 发送完成 (100%)

**错误处理**:
- `GeneratorExit`: 静默返回
- `AppError`: 写入错误运行记录，发送 `sse_error`
- `Exception`: 写入错误运行记录，发送通用错误

## 九、进度跟踪 (outline_generation_stream_progress_service.py)

**文件路径**: `backend/app/services/outline_generation_stream_progress_service.py`

### 9.1 进度状态类

#### _SegmentProgressState
| 字段 | 类型 | 说明 |
|------|------|------|
| last_ping | float | 上次心跳时间 |
| last_message | str | 上次进度消息 |
| last_snapshot_key | tuple \| None | 上次快照的去重键 |
| last_raw_preview_key | tuple \| None | 上次预览的去重键 |

#### _FillProgressState
| 字段 | 类型 | 说明 |
|------|------|------|
| last_ping | float | 上次心跳时间 |
| last_message | str | 上次进度消息 |
| last_snapshot_marker | tuple \| None | 上次快照标记 |

### 9.2 iter_segment_progress_sse_events 方法

**功能**: 轮询分段生成的进度事件并转化为 SSE 事件。

**机制**:
- 在 while 循环中等待 future 完成
- 定期发送心跳（按 `heartbeat_interval`）
- 加锁读取进度事件队列
- 对每个快照调用 `_map_segment_snapshot` 转化

### 9.3 iter_fill_progress_sse_events 方法

**功能**: 轮询填充进度事件并转化为 SSE 事件。

**机制**: 与 segment 类似，调用 `_map_fill_snapshot` 转化。

### 9.4 _map_segment_snapshot 方法

**功能**: 将分段进度快照映射为 SSE 事件。

**映射规则**:
1. **章节快照事件** (batch_applied, fill_attempt_applied, fill_gap_repair_applied, fill_gap_repair_final_sweep_applied):
   - 发送 `sse_result` 包含 outline_md 和 chapters
   - 使用 `(event_name, batch_idx, attempt, completed_count)` 作为去重键
2. **原始输出预览**: 如果有 raw_output_preview，发送 `sse_chunk`
3. **进度消息**: 使用 `progress_message_builder` 生成消息，发送 `sse_progress`

### 9.5 _map_fill_snapshot 方法

**功能**: 将填充进度快照映射为 SSE 事件。

**映射规则**:
1. **章节快照事件** (attempt_applied, gap_repair_applied, gap_repair_final_sweep_applied):
   - 发送 `sse_result` 包含 outline_md 和 chapters
2. **进度消息**: 使用 `progress_message_builder` 生成消息

### 9.6 _build_segment_raw_preview_chunk 方法

**功能**: 构建分段原始输出预览的文本块。

**格式**: `[event_name | batch X/Y | attempt Z]\n{raw_preview}`

## 十、流式终结 (outline_generation_stream_finalize_service.py)

**文件路径**: `backend/app/services/outline_generation_stream_finalize_service.py`

### 10.1 sanitize_outline_stream_result 方法

## 十三、载荷规范化 (outline_payload_normalizer.py)

**文件路径**: `backend/app/services/outline_payload_normalizer.py`

### 13.1 parse_outline_structure_json 方法

**功能**: 安全解析大纲结构 JSON 字符串。

**规则**: 如果为空或解析失败，返回 None。

### 13.2 normalize_outline_content_and_structure 方法

**功能**: 标准化大纲内容和结构数据。

**参数**: content_md (Markdown 文本), structure (已有结构数据)

**返回**: `(outline_md, structure, auto_parsed)` 三元组

**逻辑**:
1. 如果 `structure` 已存在，直接返回（不重新解析）
2. 如果 content_md 为空，返回 None 结构
3. 尝试使用 `parse_outline_output` 解析 content_md:
   - 如果解析成功且得到有效的 chapters 列表:
     - 提取 outline_md（优先使用解析出的 outline_md，回退到原始文本）
     - 返回 `(outline_md, {"chapters": chapters}, True)`
   - 如果解析失败:
     - 返回 `(text, None, False)`

## 十四、大纲存储 (outline_store.py)

**文件路径**: `backend/app/services/outline_store.py`

### 14.1 ensure_active_outline 方法

**功能**: 确保项目有一个活跃的大纲对象。

**参数**: db (数据库会话), project (项目对象)

**返回**: `Outline` 对象

**流程**:
1. 检查 `project.active_outline_id` 是否存在
2. 如果存在，尝试从数据库获取对应的 Outline 记录
3. 如果记录存在，直接返回
4. 如果不存在（项目没有活跃大纲或记录丢失）:
   - 创建新的 Outline 记录:
     - id: 新生成的唯一 ID
     - project_id: 当前项目 ID
     - title: "默认大纲"
     - content_md: 空字符串
     - structure_json: None
   - 将新记录添加到数据库
   - 更新 `project.active_outline_id`
   - 提交并刷新
   - 返回新记录

## 附录：SSE 事件流程图

### 单次模式 SSE 事件序列

```
sse_progress(0%)    -> "准备生成..."
sse_progress(10%)   -> "调用模型..."
sse_chunk(delta)    -> 流式内容分片（多次）
sse_heartbeat()     -> 每12个chunk一次
sse_progress(N%)    -> "生成中..." (动态进度)
sse_progress(90%)   -> "解析输出..."
[sse_progress(92%)  -> "尝试修复 JSON..." (仅OpenAI,如果解析失败)]
sse_result({...})   -> 预览结果（章节快照）
sse_progress(94%)   -> "补全缺失章节..."
[sse_result({...})  -> 填充过程中的章节快照更新（多次）]
sse_progress(94%)   -> 填充进度消息（多次）
sse_progress(100%)  -> "完成"
sse_result({...})   -> 最终结果
sse_done()          -> 结束
```

### 分段模式 SSE 事件序列

```
sse_progress(0%)    -> "准备生成..."
sse_progress(10%)   -> "长篇模式：分段生成中..."
sse_heartbeat()     -> 定期心跳
sse_result({...})   -> 批次应用后的章节快照（多次）
sse_chunk(...)      -> 原始输出预览（多次）
sse_progress(N%)    -> 分段进度消息（动态）
sse_progress(100%)  -> "完成"
sse_result({...})   -> 最终结果
sse_done()          -> 结束
```
