# 08 - 后端服务层：记忆系统

## 一、记忆系统整体架构

AI小说写作平台的记忆系统是一套多层级、多模态的上下文管理体系，负责在章节生成、续写、分析等流程中向 LLM 提供必要的故事背景信息。整个记忆系统由以下子系统组成：

| 子系统 | 核心服务文件 | 职责 |
|--------|-------------|------|
| 故事记忆 (Story Memory) | `memory_query_service.py`、`memory_retrieval_service.py`、`memory_update_service.py`、`memory_auto_update_app_service.py` | 管理章节摘要、伏笔、情节记忆等 |
| 结构化记忆 (Structured Memory) | `memory_update_service.py` | 实体、关系、事件、伏笔、证据的 CRUD |
| 分形记忆 (Fractal Memory) | `fractal_memory_service.py` | 多层级时间窗口记忆压缩与检索 |
| 向量 RAG 系统 | `vector_rag_service.py`、`vector_kb_service.py`、`embedding_service.py`、`rerank_service.py`、`vector_embedding_overrides.py`、`vector_rerank_overrides.py` | 向量检索增强生成 |
| 世界观百科 (Worldbook) | `worldbook_service.py`、`worldbook_auto_update_service.py` | 世界设定词条触发与自动更新 |

所有子系统的输出最终在 `memory_retrieval_service.py` 的 `retrieve_memory_context_pack()` 中统一整合为 `MemoryContextPackOut`，提供给生成流程使用。

## 二、记忆查询预处理服务 (`memory_query_service.py`)

该服务负责用户查询文本的标准化预处理，使其更适合记忆检索。

### 2.1 `parse_query_preprocessing_config(raw_json)`
- 解析 `QueryPreprocessingConfig` JSON 配置
- 若 JSON 为空或解析失败返回 `None`

### 2.2 `normalize_query_text(*, query_text, config)`
主查询标准化函数，返回 `(normalized_text, observability_dict)`。

处理流程：
1. **tag_extract**：从查询中提取 `#标签`（支持中英文），如配置了允许的标签列表则过滤
2. **exclusion_rules**：按配置的排除规则移除指定文本片段
3. **index_ref_enhance**：识别「第N章」或「chapter N」引用，追加 `chapter:N` 索引引用增强
4. **basic_clean**：合并多余空白，去除首尾空格

可观测性字典包含：`enabled`、`raw_query_text`、`normalized_query_text`、`extracted_tags`、`ignored_tags`、`applied_exclusion_rules`、`index_refs`、`steps`。

## 三、记忆检索服务 (`memory_retrieval_service.py`)

这是记忆系统的核心汇总服务，负责从所有记忆子系统中检索相关上下文并打包。

### 3.1 常量与配置

| 常量 | 值 | 含义 |
|------|---|------|
| `_MEMORY_TEXT_MD_CHAR_LIMIT` | 6000 | 默认记忆文本字符上限 |
| `_MAX_BUDGET_CHAR_LIMIT` | 50000 | 预算字符上限 |
| `_ALLOWED_SECTIONS` | 9 个 section | worldbook / story_memory / semantic_history / foreshadow_open_loops / structured / tables / vector_rag / graph / fractal |

### 3.2 辅助函数

- **`_clamp_char_limit(value, *, default)`**：将字符限制钳制到 `[0, 50000]` 范围
- **`_unwrap_text_md_block(*, text_md, tag)`**：去除 `<tag>...</tag>` 外层包裹
- **`_wrap_block_with_inner_limit(*, tag, inner, char_limit, ellipsis)`**：包裹内容并截断
- **`_wrap_and_truncate_block(*, tag, inner, char_limit)`**：完整包裹与截断逻辑
- **`_vector_rerank_config(*, db, project_id)`**：获取项目级重排序配置
- **`_extract_query_tokens(query_text, *, limit)`**：从查询中提取检索 token（最少 2 字符）

### 3.3 格式化函数

- **`_format_story_memory_text_md(*, memories, char_limit)`**：将故事记忆列表格式化为 `<StoryMemory>` 标签包裹的 Markdown（每条记忆限 800 字符）
- **`_format_semantic_history_text_md(*, memories, chapters_by_id, char_limit)`**：格式化语义历史为 `<SemanticHistory>` 包裹文本（每条限 1000 字符）
- **`_format_foreshadow_open_loops_text_md(*, foreshadows, char_limit)`**：格式化未解决伏笔为 `<ForeshadowOpenLoops>` 文本
- **`_format_structured_text_md(*, entities, relations, events, foreshadows, char_limit)`**：格式化结构化记忆（实体/关系/事件/伏笔）为 `<StructuredMemory>` 文本

### 3.4 `retrieve_memory_context_pack()`

**核心方法**，汇总所有记忆源，返回 `MemoryContextPackOut`。

参数：
- `db`：数据库会话
- `project_id`：项目 ID
- `query_text`：查询文本
- `include_deleted`：是否包含已删除条目
- `section_enabled`：各 section 启用/禁用映射
- `budget_overrides`：各 section 字符预算覆盖

**检索流程**：

1. **Worldbook 世界书**（默认启用，预算 12000 字符）
   - 调用 `preview_worldbook_trigger()` 获取触发词条
   - 解析匹配来源（constant / keyword / alias / regex / pinyin）

2. **Story Memory 故事记忆**（默认启用，预算 6000 字符）
   - 按重要性和更新时间排序
   - 支持查询 token 模糊匹配过滤
   - 最多返回 40 条，文本格式化取前 12 条

3. **Semantic History 语义历史**（默认禁用）
   - 通过 `vector_rag_service.query_project()` 查询向量索引
   - 限定 source=story_memory，memory_type=chapter_summary
   - 最多选取 8 条匹配结果

4. **Foreshadow Open Loops 未解决伏笔**（默认禁用）
   - 查询 `is_foreshadow=1` 且 `foreshadow_resolved_at_chapter_id IS NULL` 的记忆
   - 按时间线和重要性排序

5. **Structured Memory 结构化记忆**（默认启用，预算 6000 字符）
   - 查询实体（限 20）、关系（限 40）、事件（限 20）、伏笔（限 20）
   - 关系展示时解析实体名称

6. **Tables 数值表**（默认禁用）
   - 调用 `build_tables_context_text_md()` 构建表格上下文

7. **Graph 知识图谱**（默认启用，预算 6000 字符）
   - 调用 `query_graph_context()` 获取图谱上下文

8. **Vector RAG**（默认启用，预算按配置）
   - 调用 `query_project()` 或 `vector_rag_status()`

9. **Fractal Memory 分形记忆**（默认启用，预算按配置）
   - 调用 `get_fractal_context()` 获取分形记忆
   - 若有查询文本，通过 `enrich_fractal_context_for_query()` 进行长期索引检索增强

最后生成详细的日志记录（`logs` 列表），包含每个 section 的启用状态、token 估计、截断情况、预算来源等。

## 四、记忆更新服务 (`memory_update_service.py`)

该服务负责结构化记忆的完整生命周期管理，包括变更集的提议、应用和回滚。

### 4.1 数据模型映射

```python
_MODEL_BY_TABLE = {
    "entities": MemoryEntity,
    "relations": MemoryRelation,
    "events": MemoryEvent,
    "foreshadows": MemoryForeshadow,
    "evidence": MemoryEvidence,
    "project_table_rows": ProjectTableRow,
}
```

### 4.2 辅助函数

- **`_row_payload(target_table, row)`**：将 ORM 行转为标准化字典，支持 entities/relations/events/foreshadows/evidence/project_table_rows
- **`_load_target_row(db, *, target_table, project_id, target_id)`**：按类型和 ID 加载目标行
- **`_change_set_to_dict(change_set)`**：ChangeSet 序列化
- **`_change_set_summary_to_dict(*, change_set, chapter_id)`**：ChangeSet 摘要序列化
- **`_item_to_dict(item)`**：ChangeSetItem 序列化

### 4.3 ChangeSet 列表查询

#### `list_memory_change_sets(*, db, project_id, status, before, limit)`
- 分页查询变更集列表
- 支持状态过滤：proposed / applied / rolled_back / failed
- 支持时间游标分页（`before` 参数）
- JOIN `GenerationRun` 获取关联 chapter_id

#### `list_memory_tasks(*, db, project_id, status, before, limit)`
- 分页查询记忆任务列表
- 支持状态过滤：queued / running / failed / done / succeeded
- 包含任务计时信息（队列延迟、运行时长、总耗时）

### 4.4 任务管理

#### `memory_task_to_dict(*, task, change_set_request_id)`
- 序列化 MemoryTask 为字典
- 包含错误信息脱敏（`redact_api_keys`）

#### `retry_memory_task(*, db, request_id, task)`
- 幂等重试失败任务
- 重置状态为 `queued`，清除错误/结果/计时
- 增加 `retry_count`
- 通过任务队列重新入队

### 4.5 变更集提议

#### `propose_chapter_memory_change_set(*, db, request_id, actor_user_id, chapter, payload)`
- 基于 `MemoryUpdateV1Request` 提议变更集
- **幂等性**：通过 `idempotency_key` 去重
- 创建 `GenerationRun` 记录
- 逐条处理 ops：
  - **upsert**：按 `AFTER_MODEL_BY_TABLE` 验证 after 数据
  - 实体自动匹配：当缺少 `target_id` 时按 `entity_type + name` 查找现有实体
  - 关系自动匹配：按 `from_entity_id + to_entity_id + relation_type` 查找
  - 新建时自动分配 `new_id()`
  - **delete**：验证目标存在
- 记录 `before_json`（快照）和 `after_json`

#### `propose_project_table_change_set(*, db, request_id, actor_user_id, project_id, payload)`
- 专为数值表（ProjectTable）设计的变更集提议
- 支持按 key-value schema 的唯一键匹配现有行
- 自动计算 `row_index`

### 4.6 变更集应用与回滚

#### `_apply_upsert(db, *, target_table, project_id, target_id, after)`
- 按目标表类型执行 upsert 操作
- 支持所有 6 种表类型
- 自动清除 `deleted_at` 标志（恢复软删除）
- 处理 `attributes_json` 的 dict/string/None 三种情况

#### `apply_memory_change_set(*, db, request_id, actor_user_id, change_set)`
- 应用已提议的变更集
- 仅 `proposed` 状态可应用
- 逐条执行 item 的 upsert/delete 操作
- 失败时标记 `change_set.status = "failed"`
- 成功后触发向量索引重建和分形记忆重建

#### `rollback_memory_change_set(*, db, request_id, actor_user_id, change_set)`
- 回滚已应用的变更集
- 将每条 item 恢复到 `before_json` 状态
- 若 before 为 None（新建的），则软删除

## 五、记忆自动更新应用服务 (`memory_auto_update_app_service.py`)

该服务封装了记忆自动更新的完整编排流程。

### 5.1 数据类

```python
@dataclass(frozen=True, slots=True)
class PreparedMemoryAutoProposeRequest:
    project_id: str
    resolved_api_key: str
    prompt_system: str
    prompt_user: str
    prompt_messages: list[object]
    prompt_render_log_json: str | None
    llm_call: PreparedLlmCall
    idempotency_key: str
```

### 5.2 `resolve_task_llm_for_call()`
- 解析任务级 LLM 配置
- 验证 provider 一致性

### 5.3 `require_chapter_done_for_memory_update()`
- 校验章节状态必须为 `done`
- 管理员在 `allow_draft=True` 时可跳过检查

### 5.4 `prepare_memory_auto_propose_request()`
准备自动提议请求的全部参数：
1. 验证章节编辑权限
2. 验证章节状态
3. 解析 LLM 配置
4. 确保 `memory_update_v1` 提示词预设存在
5. 渲染提示词（传入章节 ID、编号、标题、规划、内容、焦点）

### 5.5 `auto_propose_chapter_memory_update()`
执行自动记忆更新的完整流程：
1. 调用 `prepare_memory_auto_propose_request()` 准备请求
2. 覆盖 LLM 参数：`temperature=0.2, max_tokens=2048`
3. 调用 LLM 并记录
4. 通过 `contract_for_task("memory_update")` 解析输出
5. 构建 `MemoryUpdateV1Request`
6. 调用 `propose_chapter_memory_change_set()` 提交提议

## 六、分形记忆服务 (`fractal_memory_service.py`)

分形记忆是一种多层级时间窗口的记忆压缩系统，模拟人类「近期清晰、远期模糊」的记忆特性。

### 6.1 核心配置

```python
@dataclass(frozen=True, slots=True)
class FractalConfig:
    scene_window: int        # 场景窗口大小（多少章节合为一个 arc）
    arc_window: int          # 弧窗口大小（多少 arc 合为一个 saga）
    char_limit: int          # 注入文本字符上限
    recent_window_chapters: int   # 近期窗口章节数
    mid_window_chapters: int      # 中期窗口章节数
    long_window_chapters: int     # 长期窗口章节数
    long_index_terms: int         # 长期索引关键词数
    long_retrieval_hits: int      # 长期检索最大命中数
```

### 6.2 辅助函数

- **`_to_scene_summary(chapter)`**：提取章节摘要（优先 summary > content 前 280 字 > plan 前 200 字 > title）
- **`_extract_keywords(text, *, limit)`**：按词频提取关键词（最少 2 字符）
- **`_sample_scene_lines(*, scenes, max_items)`**：从场景列表中采样（头部 3 条 + 中间 + 尾部 2 条的策略）
- **`_build_fractal_prompt_inner()`**：构建分形记忆注入文本

### 6.3 `compute_fractal()`

核心计算函数，构建多层级记忆结构：

**层级结构**：
1. **Scenes（场景层）**：每个已完成章节 → 一个 scene（含 chapter_id, number, title, summary_md）
2. **Arcs（弧层）**：每 `scene_window` 个 scene 合为一个 arc
3. **Sagas（传奇层）**：每 `arc_window` 个 arc 合为一个 saga

**分层存档（Layered Archive）**：
- **recent_window**：最近 N 章的完整场景数据
- **mid_term**：每 `mid_window_chapters` 章的采样摘要（每段最多 8 条场景线，限 2600 字符）
- **long_term**：每 `long_window_chapters` 章的长期总纲（含关键词索引）

**输出**：
- 注入文本包裹在 `<FractalMemory>...</FractalMemory>` 标签中
- 包含预算可观测性数据（dropped items、budget limits）

### 6.4 `select_fractal_long_term_hits()`

基于查询文本的长期索引命中检索：
- 从 long_term outlines 中提取关键词
- 与查询 tokens 进行关键词匹配和摘要匹配
- 评分：`关键词命中 * 3 + 摘要命中`
- 按评分排序，限制 `max_hits`

### 6.5 `enrich_fractal_context_for_query()`

用查询结果增强分形上下文：
- 调用 `select_fractal_long_term_hits()` 获取长期命中
- 重建注入文本（包含最近窗口 + 最新中期阶段 + 最新长期总纲 + 长期命中）
- 更新 `prompt_block` 和 `text_md`

### 6.6 `get_fractal_context()`

从数据库加载已构建的分形记忆上下文：
- 解析 `FractalMemory` 表的 JSON 字段
- 重建层级结构和注入文本
- 支持 v2 摘要（LLM 生成的压缩摘要，包裹在 `<FractalMemoryV2>` 中）

### 6.7 `rebuild_fractal_memory()`

重建分形记忆（确定性计算）：
- 加载项目所有 done 章节
- 调用 `compute_fractal()` 计算
- 持久化到 `FractalMemory` 表

### 6.8 `rebuild_fractal_memory_v2()`

LLM 增强重建（v2）：
1. 先执行确定性重建作为基线
2. 从最新 saga 摘要中提取内容
3. 通过 `fractal_v2_v1` 资源渲染提示词
4. 调用 LLM（temperature=0.3, max_tokens=1024）生成压缩摘要
5. 任何 LLM 失败都回退到确定性输出

## 七、向量 RAG 系统

### 7.1 知识库管理服务 (`vector_kb_service.py`)

管理项目级的知识库（Knowledge Base）配置。

#### 方法详解

- **`ensure_default_kb(db, *, project_id)`**：确保项目有 `default` 知识库
- **`list_kbs(db, *, project_id)`**：列出所有 KB（按 order_index 排序）
- **`get_kb(db, *, project_id, kb_id)`**：获取单个 KB
- **`create_kb(db, *, project_id, name, kb_id, enabled, weight, priority_group)`**：
  - 自动生成 `kb_<uuid>` 格式 ID
  - 验证 `kb_id` 格式（字母数字下划线横杠，最长 64）
  - 支持 `normal` / `high` 优先级组
- **`update_kb(db, *, project_id, kb_id, name, enabled, weight, priority_group)`**：部分更新
- **`delete_kb(db, *, project_id, kb_id)`**：删除 KB（需先禁用，default 不可删）
- **`reorder_kbs(db, *, project_id, ordered_kb_ids)`**：重排序所有 KB
- **`resolve_query_kbs(db, *, project_id, requested_kb_ids)`**：解析查询时使用的 KB 列表（指定 > 启用 > default）

### 7.2 向量检索服务 (`vector_rag_service.py`)

核心向量检索服务，支持 pgvector 和 ChromaDB 两种后端。

#### 7.2.1 后端选择

- **`_is_postgres()`**：判断是否 PostgreSQL
- **`_pgvector_ready()`**：检查 pgvector 扩展和表是否就绪（30 秒 TTL 缓存）
- **`_prefer_pgvector()`**：根据配置选择后端（auto / chroma / pgvector）

#### 7.2.2 数据结构

```python
@dataclass(frozen=True, slots=True)
class VectorChunk:
    id: str
    text: str
    metadata: dict[str, Any]

VectorSource = Literal["worldbook", "outline", "chapter", "story_memory"]
```

#### 7.2.3 候选合并

- **`_merge_kb_candidates_rrf()`**：使用加权 RRF (Reciprocal Rank Fusion) 合并多 KB 候选
  - `score = weight * 1/(k + rank)`
  - 确定性排序：score desc → kb_order asc → distance asc → id asc
- **`_merge_kb_candidates()`**：带优先级组的合并
  - high 优先级 KB 先填满 top_k
  - 不足时再从 normal 优先级补充

#### 7.2.4 重排序集成

- **`_rerank_score()`**：本地重排序评分
  - `rapidfuzz_token_set_ratio`：模糊匹配评分
  - `token_overlap`：token 重叠率
- **`_rerank_candidates()`**：调用 `rerank_service.rerank_candidates`

#### 7.2.5 超级排序

- **`_super_sort_final_chunks()`**：最终 chunk 的跨 source 排序
  - 支持 source_order 和 source_weights 配置
  - 使用加权轮询算法实现公平分配

#### 7.2.6 核心查询

- **`query_project(project_id, query_text, ...)`**：项目级向量查询
- **`vector_rag_status(project_id, ...)`**：查询向量服务状态
- **`build_project_chunks()`**：构建项目所有 source 的 chunks
- **`rebuild_project()`**：重建项目向量索引
- **`ingest_chunks()`**：批量写入向量 chunks
- **`purge_project_vectors()`**：清除项目所有向量数据
- **`schedule_vector_rebuild_task()`**：调度向量重建任务

#### 7.2.7 预算可观测性

```python
_VECTOR_DROPPED_REASON_EXPLAIN = {
    "duplicate_chunk": "同一 source/source_id/chunk_index 已存在于最终候选，避免重复注入。",
    "per_source_budget": "同一 source+source_id 的 chunk 数达到上限。",
    "budget": "达到最终注入 chunk 上限。",
}
```

### 7.3 嵌入服务 (`embedding_service.py`)

多 provider 嵌入向量生成服务。

#### 支持的 Provider

| Provider | 类型 | 说明 |
|----------|------|------|
| `openai_compatible` | 远程 | OpenAI 兼容 API（默认） |
| `azure_openai` | 远程 | Azure OpenAI 服务 |
| `google` | 远程 | Google Gemini 嵌入 |
| `custom` | 远程 | 自定义 API |
| `local_proxy` | 远程 | 本地代理 |
| `sentence_transformers` | 本地 | 本地 sentence-transformers 模型 |

#### 方法详解

- **`EmbeddingConfig`**：Pydantic 配置模型
  - 支持 provider 别名解析（openai→openai_compatible, gemini→google, st→sentence_transformers）
  - 自动兼容填充（azure_deployment←model, sentence_transformers_model←model）
- **`resolve_embedding_config(embedding)`**：合并环境变量与覆盖配置
- **`embedding_enabled_reason(config)`**：检查配置是否完整，返回 `(enabled, disabled_reason)`
- **`embed_texts(texts, *, embedding)`**：主嵌入函数，路由到对应 provider
- **`_embed_openai_compatible()`**：POST `/embeddings`
- **`_embed_azure_openai()`**：POST `/openai/deployments/{deployment}/embeddings`
- **`_embed_google_gemini()`**：支持单条 `embedContent` 和批量 `batchEmbedContents`
- **`_embed_sentence_transformers()`**：本地模型推理，支持线程安全缓存

### 7.4 重排序服务 (`rerank_service.py`)

候选结果重排序服务，支持本地和远程方法。

#### 方法策略

| 方法 | 类型 | 说明 |
|------|------|------|
| `rapidfuzz_token_set_ratio` | 本地 | 模糊 token 集合相似度 |
| `token_overlap` | 本地 | token 重叠率 |
| `external_rerank_api` | 远程 | 外部 rerank API |

#### `rerank_candidates()`
- **Plan 机制**：`auto` → rapidfuzz → token_overlap（逐级降级）
- **混合排序**：支持 `hybrid_alpha` 混合原始排序与重排序结果
  - `score = alpha * base_rank + (1 - alpha) * rerank_rank`
- **错误容忍**：任何方法失败自动尝试下一个

#### `_external_rerank_candidates()`
- 调用外部 `/rerank` API
- 自适应解析响应格式（results / data / list）
- 支持多种字段名（index/idx/document_index, score/relevance_score/similarity）

### 7.5 嵌入覆盖服务 (`vector_embedding_overrides.py`)

- **`vector_embedding_overrides(row)`**：
  - 提取 provider、base_url、model、azure_deployment、azure_api_version、sentence_transformers_model
  - 自动解密 `api_key_ciphertext`

### 7.6 重排序覆盖服务 (`vector_rerank_overrides.py`)

从 `ProjectSettings` 中解析项目级重排序配置覆盖。

- **`vector_rerank_overrides(row)`**：
  - 合并项目覆盖与环境变量配置
  - 返回完整配置：enabled、method、top_k、provider、base_url、model、timeout_seconds、hybrid_alpha、api_key

## 八、世界观百科系统

### 8.1 世界书服务 (`worldbook_service.py`)

管理世界设定词条的触发和检索。

#### 8.1.1 关键词匹配机制

- **`_keyword_matches(*, base, keyword)`**：
  - 普通包含匹配：`keyword in base`
  - 单词边界匹配：`word:xxx` → 使用正则避免 "he" 匹配 "the"

- **`_split_aliases(keyword)`**：解析别名语法（`alias:xxx|yyy` 或 `xxx|yyy`）

- **`_contains_pinyin_match(text, query_ascii, *, cache)`**：拼音匹配支持
  - 使用 `pypinyin` 库生成全拼和首字母拼音
  - 线程安全缓存

#### 8.1.2 触发引擎

**`_trigger_entries()`**：核心触发逻辑

1. **常量触发**：`constant=True` 的词条始终触发
2. **关键词匹配**（多轮递归）：
   - 基础关键词包含匹配
   - 别名匹配（`alias_enabled`）
   - 正则匹配（`regex_enabled` + 白名单限制）
   - 拼音匹配（`pinyin_enabled`）
3. **递归扩展**：已触发词条的内容加入搜索文本（尊重 `prevent_recursion` / `exclude_recursion`）
4. 最大递归轮数 = 待处理词条数 + 1

#### 8.1.3 优先级与排序

- **`_priority_rank(value)`**：must=3, important=2, optional=1, 其他=0
- **`_sort_triggered_entries()`**：constant 优先 → priority 降序 → 更新时间降序 → title → id
- **`_apply_trigger_limit()`**：限制触发总数

#### 8.1.4 文本格式化

**`_format_worldbook_text()`**：
- 每个词条格式：`【世界书条目：{title} | {reason} | priority:{priority}】\n{content}`
- 词条间以 `---` 分隔
- 整体包裹在 `<WORLD_BOOK>...</WORLD_BOOK>` 标签中
- 支持每条词条独立的 `char_limit`

#### 8.1.5 `preview_worldbook_trigger()`

公共预览接口：
- 支持术语表查询扩展（`glossary_query_expand_enabled`）
- 返回 `WorldBookPreviewTriggerOut`（触发词条列表、text_md、truncated）

### 8.2 世界书自动更新服务 (`worldbook_auto_update_service.py`)

基于 LLM 的世界书自动更新。

#### 8.2.1 常量配置

| 配置 | 默认值 | 说明 |
|------|--------|------|
| 章节摘要最大字符 | 4000 | 可通过环境变量覆盖 |
| 章节内容最大字符 | 40000 | 可通过环境变量覆盖 |
| 最大已有标题数 | 200 | 提示词中包含的已有标题数上限 |
| 已有条目预览限制 | 60 | 提供给 LLM 的已有条目预览数 |
| 每条关键词限制 | 20 | 每条预览的关键词数上限 |
| 内容预览字符 | 400 | 已有条目内容预览字符数 |

#### 8.2.2 `build_worldbook_auto_update_prompt_v1()`

构建自动更新提示词：
- **System prompt**：定义 JSON 输出契约
  - 支持 4 种操作：create / update / merge / dedupe
  - 严格约束优先级枚举：drop_first / optional / important / must
  - 要求填写 reason 字段
- **User prompt**：包含 project_id、world_setting、existing_worldbook_titles（JSON 列表）、existing_worldbook_entries_preview、outline_md、chapter_summary、chapter_content_md

#### 8.2.3 操作解析

- **create**：新建条目（title, content_md, keywords, aliases, enabled, constant, priority 等）
- **update**：按 match_title 匹配现有条目进行补丁更新
- **merge**：合并模式（append_missing / append / replace）
- **dedupe**：指定 canonical_title 和 duplicate_titles 进行去重

#### 8.2.4 关键词构建

**`_build_keywords(*, title, keywords, aliases)`**：
- 合并 title + keywords + aliases
- 去重（大小写不敏感），限 40 条
