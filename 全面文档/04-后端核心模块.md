## 一、应用入口 (main.py)

文件路径: `backend/app/main.py`

### 1.1 FastAPI 应用创建

```python
app = FastAPI(title="ainovel", version=settings.app_version, lifespan=lifespan)
```

应用以 `ainovel` 为标题，版本号取自配置 `app_version`（默认 `"0.1.0"`），使用 `lifespan` 异步上下文管理器控制启动和关闭行为。

### 1.2 Lifespan 生命周期管理

`lifespan` 函数是一个 `@asynccontextmanager` 装饰的异步生成器，控制应用从启动到关闭的完整生命周期：

**启动阶段（yield 之前）：**

1. **配置日志系统** - 调用 `configure_logging()` 初始化 loguru + 标准库拦截。
2. **条件性数据库初始化** - 通过 `_should_bootstrap_in_app()` 判断是否需要在当前进程中进行数据库初始化：
   - 如果环境变量 `AINOVEL_BOOTSTRAP_DONE=true`，跳过（表示已由外部脚本完成）。
   - 如果环境变量 `AINOVEL_BOOTSTRAP_IN_APP` 有值，按该值决定。
   - 否则仅在 `dev` 环境且 `WEB_CONCURRENCY <= 1` 时自动执行。
   - 执行时调用 `ensure_db_schema()` 进行数据库迁移，以及 `_ensure_admin_user()` 创建管理员账户。
3. **SQLite 单 worker 警告** - 当使用 SQLite 时打印警告日志，提醒只能用单 worker 运行。
4. **确保本地开发用户存在** - `_ensure_local_user()` 在 dev 环境下，如果 `auth_dev_fallback_user_id` 已配置，自动在 `users` 表中创建该 fallback 用户（display_name 为 "本地用户"）。
5. **启动任务看门狗** - `start_project_task_watchdog()` 启动项目任务运行时的监控线程。

**关闭阶段（yield 之后）：**

1. **停止任务看门狗** - `stop_project_task_watchdog()`。
2. **关闭 LLM HTTP 客户端** - `close_llm_http_client()` 关闭所有线程局部 httpx 客户端。

### 1.3 CORS 中间件

```python
app.add_middleware(
    CORSMiddleware,
    allow_origins=settings.cors_origins_list() or ([] if settings.app_env == "prod" else ["http://localhost:5173"]),
    allow_credentials=True,
    allow_methods=["*"],
    allow_headers=["Content-Type", "Authorization", "X-LLM-Provider", "X-LLM-API-Key"],
    expose_headers=["X-Request-Id"],
)
```

- **allow_origins**: 从配置中读取逗号分隔的域名列表；生产环境不设默认值，开发环境默认 `http://localhost:5173`（Vite 默认端口）。
- **allow_credentials**: `True`，允许跨域携带 Cookie（会话认证需要）。
- **allow_methods**: `["*"]`，所有 HTTP 方法。
- **allow_headers**: 明确列出 `Content-Type`、`Authorization`、`X-LLM-Provider`、`X-LLM-API-Key` 四个自定义/标准头。
- **expose_headers**: 将 `X-Request-Id` 暴露给前端 JavaScript。

### 1.4 认证会话中间件

```python
@app.middleware("http")
async def auth_session_middleware(request, call_next)
```

此中间件在每个请求上执行：

1. 初始化 `request.state` 四个属性：`user_id`、`authenticated_user_id`、`session_expire_at`、`auth_source`，全部设为 `None`。
2. 从 Cookie 中读取 `user_id` Cookie（名称可配置），调用 `decode_session_cookie()` 解码并验签。
3. 如果 Cookie 有效，设置 `request.state.user_id`、`authenticated_user_id`、`session_expire_at`、`auth_source = "session"`。
4. 如果 Cookie 无效，在 dev 环境下使用 `auth_dev_fallback_user_id` 作为 fallback 用户，`auth_source = "dev_fallback"`。

### 1.5 请求 ID 与日志中间件

```python
@app.middleware("http")
async def request_id_and_logging_middleware(request, call_next)
```

1. 从请求头 `X-Request-Id` 获取请求 ID，若无则生成 UUID。
2. 将请求 ID 存入 `request.state.request_id` 和 ContextVar。
3. 记录请求开始时间（`time.perf_counter()`）。
4. 请求完成后计算延迟（毫秒），状态码 < 400 时记录 info 级别日志。
5. 对已认证用户的 API 请求（排除 `/api/health` 和 OPTIONS），调用 `touch_user_activity()` 更新用户最后活动时间。
6. 在响应头中添加 `X-Request-Id`。
7. 在 `finally` 块中重置 ContextVar。

### 1.6 异常处理器

共注册 4 个异常处理器：

| 异常类型 | 处理方式 | HTTP 状态码 |
|---|---|---|
| `AppError` | 记录 warning/error 日志，返回结构化 JSON `{ok, error, request_id}` | 由 `AppError.status_code` 决定 |
| `RequestValidationError` | 提取安全字段 `(loc, msg, type)`，返回 `VALIDATION_ERROR` | 400 |
| `SQLAlchemyError` | 记录 error 日志（含异常指纹），返回 `DB_ERROR` | 500 |
| `Exception`（兜底） | 记录 error 日志（含异常指纹），返回 `INTERNAL_ERROR` | 500 |

所有错误响应均包含 `X-Request-Id` 响应头。

### 1.7 路由注册

```python
app.include_router(api_router)
```

所有 API 路由通过 `app.api.router.api_router` 统一注册。

### 2.4 模型验证器

`_validate_crypto_config` 是一个 `@model_validator(mode="after")` 全局验证器，在所有字段验证完毕后执行以下校验：

1. **生产环境加密密钥必填** - `app_env == "prod"` 时 `secret_encryption_key` 不能为空。
2. **生产环境禁止 fallback 用户** - `app_env == "prod"` 时 `auth_dev_fallback_user_id` 必须为空。
3. **生产环境任务队列** - `app_env == "prod"` 时 `task_queue_backend` 必须为 `rq`。
4. **生产环境 CORS** - `app_env == "prod"` 时 CORS 必须配置且不能包含 `*` 或 `null`。
5. **生产环境密码强度** - `app_env == "prod"` 时管理员密码不能是弱密码（定义在 `WEAK_PROD_ADMIN_PASSWORDS` 集合中）。
6. **RQ 需要 Redis** - `task_queue_backend == "rq"` 时 `redis_url` 不能为空。

## 三、认证会话系统 (auth_session.py)

文件路径: `backend/app/core/auth_session.py`

### 3.1 会话数据结构

```python
@dataclass(frozen=True, slots=True)
class AuthSession:
    user_id: str
    expires_at: datetime
```

不可变数据类，包含用户 ID 和过期时间。

### 3.2 签名密钥获取策略

`_get_signing_key()` 函数按优先级获取签名密钥：

1. 如果 `auth_session_signing_key` 已配置，使用它（UTF-8 编码）。
2. 如果 `secret_encryption_key` 已配置，尝试 base64 URL-safe 解码，失败则直接 UTF-8 编码。
3. 否则生成随机 32 字节密钥（进程级别缓存，存储在 `_DEV_SIGNING_KEY` 全局变量中）。

### 3.3 Cookie 编码格式

格式: `v1.<payload_base64url>.<signature_base64url>`

- **版本前缀**: `v1`
- **Payload**: JSON 格式 `{"uid": "<user_id>", "exp": <unix_timestamp>}`，Base64 URL-safe 编码。
- **签名**: HMAC-SHA256(payload_bytes, signing_key)，Base64 URL-safe 编码。

### 3.4 Cookie 解码与验证

`decode_session_cookie(value, *, now=None)` 执行以下验证步骤：

1. 按 `.` 分割，必须恰好 3 部分。
2. 版本必须为 `v1`。
3. Base64 URL-safe 解码 payload。
4. HMAC 签名验证（时间安全比较 `hmac.compare_digest`）。
5. JSON 解析 payload。
6. 验证 `uid` 为非空字符串，`exp` 为正整数。
7. 过期时间检查：`expires_at > now`。

任何步骤失败返回 `None`。

### 3.5 Cookie 设置与清除

`set_session_cookies(response, *, user_id, expires_at)` 设置两个 Cookie：

| Cookie 名 | 值 | 说明 |
|---|---|---|
| `user_id`（可配置） | 签名后的会话 Cookie | 包含用户 ID 和过期时间，httponly |
| `session_expire_at`（可配置） | Unix 时间戳 | 过期时间的时间戳，httponly |

Cookie 属性：
- `httponly=True`: 防止 JS 访问。
- `secure`: 仅在 `prod` 环境启用。
- `samesite`: 取自配置。
- `max_age`: 动态计算剩余秒数。
- `path="/"`: 全路径有效。

`clear_session_cookies(response)` 删除两个 Cookie。

## 四、错误处理系统 (errors.py)

文件路径: `backend/app/core/errors.py`

### 4.1 AppError 异常类

```python
@dataclass(slots=True)
class AppError(Exception):
    code: str
    message: str
    status_code: int = 400
    details: dict[str, Any] = field(default_factory=dict)
```

核心业务异常类，同时继承 `Exception` 和使用 `dataclass` 装饰器。

**工厂方法：**

| 方法 | code | status_code | 默认 message |
|---|---|---|---|
| `unauthorized()` | `UNAUTHORIZED` | 401 | "未登录" |
| `forbidden()` | `FORBIDDEN` | 403 | "无权限" |
| `not_found()` | `NOT_FOUND` | 404 | "资源不存在" |
| `conflict()` | `CONFLICT` | 409 | "资源冲突" |
| `validation()` | `VALIDATION_ERROR` | 400 | "参数错误" |

### 4.2 响应载荷构建

- `error_payload(*, request_id, code, message, details)`: 构建标准错误响应 `{"ok": false, "error": {...}, "request_id": "..."}`。
- `ok_payload(*, request_id, data)`: 构建标准成功响应 `{"ok": true, "data": ..., "request_id": "..."}`。

## 五、日志系统 (logging.py)

文件路径: `backend/app/core/logging.py`

### 5.1 日志架构

采用 **loguru + 标准库拦截** 双层架构：

1. loguru 作为主日志后端，输出到 stderr。
2. 通过 `InterceptHandler` 拦截标准库 logger，将所有日志转发到 loguru。

### 5.2 InterceptHandler

自定义的 `logging.Handler`，在 `emit` 方法中：

1. 将标准库日志级别映射到 loguru 级别。
2. 通过栈帧回溯找到实际调用者（跳过 logging 和 importlib bootstrap 帧）。
3. 使用 `loguru_logger.opt(depth=depth, exception=record.exc_info).log()` 转发。

### 5.3 configure_logging() 函数

1. 移除 loguru 默认 handler。
2. 添加 stderr handler，日志格式为纯消息 `{message}`，dev 环境启用 backtrace。
3. 设置根 logger 使用 `InterceptHandler`。
4. 拦截以下标准库 logger: `ainovel`、`uvicorn`、`uvicorn.error`、`uvicorn.access`、`fastapi`、`httpx`、`httpcore`、`sqlalchemy`、`py.warnings`。
5. 启用 `logging.captureWarnings(True)` 捕获 Python warnings。
6. 将 `httpx` 和 `httpcore` 日志级别设为 WARNING，避免请求日志泄露敏感查询参数（如 Gemini 的 `?key=...`）。

### 5.4 敏感信息脱敏

定义了多个正则表达式对日志中的敏感信息进行脱敏：

| 正则 | 匹配目标 | 脱敏结果 |
|---|---|---|
| `_QUERY_SECRET_RE` | URL 中的 `?key=`/`?api_key=`/`?token=` 参数 | 替换值为 `****` |
| `_URL_CREDENTIALS_RE` | URL 中的 `user:pass@` 凭据 | 替换为 `***@` |
| `_KEY_TOKEN_RE` | `sk-`/`rk-`/`pk-` 开头的 API Key | 保留前缀和末4位 |
| `_GOOGLE_API_KEY_RE` | `AIza` 开头的 Google API Key | 替换为 `AIza***` |
| `_BEARER_TOKEN_RE` | Bearer 令牌 | 替换为 `bearer ***` |
| `_X_LLM_API_KEY_RE` | `x-llm-api-key` 请求头 | 替换值为 `***` |

### 5.5 安全日志详情

`safe_log_details(details, *, extra_allowed)` 过滤日志详情字段，仅保留白名单中的安全字段：

白名单: `status_code`、`upstream_error`、`compat_adjustments`、`compat_dropped_params`、`errors`、`attempts`、`attempt_max`、`provider`、`model`、`base_url_host`、`timeout_seconds`、`dropped_params`、`finish_reason`、`latency_ms`。

`upstream_error` 字段会被脱敏并截断至 500 字符。

### 5.6 异常日志字段

`exception_log_fields(exc)`:
- **dev 环境**: 返回 `exception_type`、`exception`（脱敏截断）、`stack`（完整调用栈）。
- **prod 环境**: 返回 `exception_type`、`exception_hash`（SHA-256 前 12 位，不泄露错误详情）。

### 5.7 结构化日志

`log_event(logger, level, **fields)` 输出结构化 JSON 日志：
- 自动添加 `ts`（UTC ISO 格式）和 `level`。
- 自动从 ContextVar 获取 `request_id`。
- 使用 `json.dumps` 紧凑格式输出。

## 七、密钥管理 (secrets.py)

文件路径: `backend/app/core/secrets.py`

### 7.1 加密方案概述

支持三种加密/存储方案，通过密文前缀区分：

| 前缀 | 方案 | 适用环境 | 说明 |
|---|---|---|---|
| `enc:` | Fernet 对称加密 | 所有环境 | 可跨机器迁移，生产环境唯一可用方案 |
| `dpapi:` | Windows DPAPI | dev（仅 Windows） | 使用 Windows 用户凭据加密，不可跨机器 |
| `plain:` | Base64 编码（无加密） | dev | 仅 dev 环境可用 |
| 无前缀 | 明文 | dev | 向后兼容，仅 dev 环境可用 |

### 7.2 加密流程 (encrypt_secret)

1. 如果 `app_env == "prod"` 或 `secret_encryption_key` 已配置，使用 Fernet 加密，返回 `enc:` 前缀。
2. 如果在 Windows 上，使用 DPAPI 加密，返回 `dpapi:` 前缀。
3. 在非 Windows 的 dev 环境，要求必须配置 `SECRET_ENCRYPTION_KEY`（无不安全 fallback）。

### 7.3 解密流程 (decrypt_secret)

1. `dpapi:` 前缀 -> 生产环境拒绝，非 Windows 拒绝，否则调用 DPAPI 解密。
2. `enc:` 前缀 -> Fernet 解密，密钥无效抛出 `SecretCryptoError`。
3. `plain:` 前缀 -> 生产环境拒绝，否则 Base64 解码。
4. 无前缀 -> dev 环境直接返回明文，其他环境抛出错误。

### 7.4 Windows DPAPI 集成

在 Windows 平台上，通过 `ctypes` 直接调用 `crypt32.dll` 的 `CryptProtectData` 和 `CryptUnprotectData` 函数。使用 `_CRYPTPROTECT_UI_FORBIDDEN` 标志禁止 UI 弹窗。

非 Windows 平台上，`_dpapi_encrypt` 和 `_dpapi_decrypt` 函数被替换为抛出异常的占位实现。

### 7.5 API Key 脱敏

- `mask_api_key(api_key)`: 保留前缀（如 `sk-`）和末 4 位，中间用 `****` 替代。
- `redact_api_keys(value)`: 递归遍历嵌套的 dict/list，将 `*api_key*` 字段替换为 `has_api_key` + `masked_api_key` 组合。其他包含 `api_key`/`apikey` 的字段替换为 `[REDACTED]`。

### 8.1 ORM 基类 (db/base.py)


### 8.2 会话管理 (db/session.py)

文件路径: `backend/app/db/session.py`

#### 引擎创建

```python
engine = create_engine(DATABASE_URL, connect_args=connect_args, pool_pre_ping=True, ...)
```

- **SQLite**: 设置 `check_same_thread=False`，不使用连接池参数。
- **其他数据库**: 使用配置的 `pool_size`、`max_overflow`、`pool_timeout`、`pool_recycle`。
- 启用 `pool_pre_ping=True`，每次获取连接前检测连接有效性。

#### SQLite Pragma 设置

通过 SQLAlchemy `connect` 事件，在每次 SQLite 连接建立时执行：

```sql
PRAGMA foreign_keys=ON;    -- 启用外键约束
PRAGMA journal_mode=WAL;   -- WAL 模式，提升并发读性能
PRAGMA synchronous=NORMAL; -- 平衡性能与数据安全
PRAGMA busy_timeout=5000;  -- 数据库锁定时等待 5 秒
```

#### Session 工厂

```python
SessionLocal = sessionmaker(bind=engine, autoflush=False, expire_on_commit=False)
```

- `autoflush=False`: 手动控制刷新时机。
- `expire_on_commit=False`: 提交后对象属性不过期，避免额外查询。

#### 依赖注入

```python
def get_db() -> Generator[Session, None, None]:
    db = SessionLocal()
    try:
        yield db
    finally:
        db.close()
```

FastAPI 依赖注入生成器，确保 Session 在请求结束后关闭。

### 8.3 迁移系统 (db/migrations.py)

文件路径: `backend/app/db/migrations.py`

#### ensure_db_schema() 主流程

1. 获取 Alembic 配置，指定 `alembic.ini` 路径和迁移脚本目录。
2. 使用 `engine.begin()` 开启显式事务（避免隐式事务被回滚）。
3. 对 PostgreSQL 数据库，获取 Advisory Lock 防止并发迁移：
   - 使用 `pg_try_advisory_lock` 进行轮询，默认超时 60 秒。
   - Lock ID 默认 `8260228`，可通过环境变量 `DB_MIGRATION_LOCK_ID` 配置。
4. 检查数据库表结构：
   - 如果是 SQLite 且有表但无 `alembic_version` 表（遗留数据库）：
     - 检查是否包含新 schema 特征（`outlines`、`llm_profiles` 表以及 `projects` 表中的相关列）。
     - 有新 schema 则 stamp 到 `head`，否则 stamp 到初始版本 `0f24b611cf21`。
     - 生产环境拒绝自动 stamp，要求手动操作。
   - 执行 `alembic upgrade head`。
5. 在 `finally` 中释放 Advisory Lock。

### 8.4 时间兼容层 (db/datetime_compat.py)

文件路径: `backend/app/db/datetime_compat.py`

#### 问题背景

SQLite 不原生支持时区感知的 datetime。该模块确保从数据库加载的所有 datetime 字段都是 UTC 时区感知的。

#### coerce_utc_datetime(value)

将任意值转换为 UTC 时区感知的 datetime：
- `None` 返回 `None`。
- datetime 对象：无时区则标记为 UTC，有时区则转换到 UTC。
- 字符串：处理 `Z` 后缀，使用 `fromisoformat` 解析。

#### normalize_instance_datetime_fields(instance, *, attrs=None)

仅在 SQLite 模式下生效，遍历 ORM 实例的所有 `DateTime` 类型列，将它们标准化为 UTC。

#### 自动触发

通过 SQLAlchemy 事件监听器自动触发：
- `Base.load` 事件：从数据库加载实例时自动标准化。
- `Base.refresh` 事件：刷新实例时自动标准化（只处理刷新的属性）。

## 九、SSE 响应工具 (utils/sse_response.py)

文件路径: `backend/app/utils/sse_response.py`

### 9.1 SSE 格式化

`format_sse(data, event, *, event_id, retry)` 构建符合 SSE 规范的文本：

```
id: <event_id>
event: <event>
retry: <retry>
data: <json>

```

### 9.2 预定义 SSE 事件

| 函数 | 事件类型 | 数据 type | 用途 |
|---|---|---|---|
| `sse_start()` | `start` | `"start"` | 流式任务开始通知 |
| `sse_progress()` | `progress` | `"progress"` | 进度更新（含百分比和字符数） |

| `sse_heartbeat()` | - | - | 心跳注释 `": heartbeat\n\n"` |

### 9.3 阻塞调用心跳包装

`stream_blocking_call_with_heartbeat(*, runner, start_event, heartbeat_event, heartbeat_interval_seconds)`:

使用 `ThreadPoolExecutor` 将阻塞调用移到子线程，主线程每隔 `heartbeat_interval_seconds` 秒（默认 1 秒）发送一次心跳事件，保持 SSE 连接不超时。当阻塞调用完成后，返回结果值。

### 9.4 SSE 响应创建

`create_sse_response(generator)` 创建 FastAPI `StreamingResponse`：

- `media_type`: `text/event-stream`
- `Cache-Control`: `no-cache`
- `Connection`: `keep-alive`
- `X-Accel-Buffering`: `no`（告知 Nginx 不要缓冲）

包装生成器以正确处理 `GeneratorExit` 异常，确保底层生成器被关闭。
