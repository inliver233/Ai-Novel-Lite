# 06 - 后端服务层：章节生成

## 一、章节生成完整流程概览

章节生成是整个 AI 小说写作平台的核心功能，从用户发起请求到最终内容输出，经历以下完整链路：

```
用户请求
  |
  v
chapter_generation_app_service (入口编排)
  |
  +---> prepare_chapter_generate_request (准备阶段)
  |       |
  |       +---> 权限验证 (require_chapter_editor)
  |       +---> 前置章节检查 (_require_chapter_prereqs_if_needed)
  |       +---> LLM配置解析 (resolve_task_llm_for_call)
  |       +---> 上下文构建 (build_chapter_generate_render_values)
  |       +---> 风格解析 (resolve_style_guide)
  |       +---> 记忆注入 (prepare_chapter_memory_injection)
  |       +---> MCP研究 (run_mcp_research_step)
  |       +---> 提示词渲染 (render_preset_for_task)
  |       +---> 提示词覆盖 (apply_prompt_override)
  |
  +---> [可选] plan_first 模式 => run_plan_first_step
  |       |
  |       +---> run_plan_llm_step (规划 LLM 调用)
  |       +---> inject_plan_into_render_values (将规划注入渲染值)
  |       +---> render_main_prompt (重新渲染主提示词)
  |
  +---> apply_target_word_count (长度控制)
  |
  +---> run_chapter_generate_llm_step / call_llm_stream_messages (LLM 调用)
  |
  +---> 输出解析 (contract_for_task("chapter_generate").parse)
  |
  +---> [可选] 后处理
  |       +---> post_edit (润色)
  |       +---> content_optimize (内容优化)
  |
  +---> write_generation_run (记录运行)
  |
  v
返回结果 / SSE 流式输出
```

## 二、章节生成应用服务 (chapter_generation_app_service.py)

**文件路径**: `backend/app/services/chapter_generation_app_service.py`

此文件是章节生成的顶层入口，编排整个章节生成流程。

### 2.1 plan_chapter 方法

**功能**: 独立的章节规划入口，仅生成章节写作计划而不生成正文。

**参数**:
- `logger`: 日志记录器
- `request_id`: 请求唯一标识
- `chapter_id`: 章节 ID
- `body`: `ChapterPlanRequest` 请求体
- `user_id`: 用户 ID
- `x_llm_provider` / `x_llm_api_key`: 可选的 LLM 提供商和密钥

**流程**:
1. 调用 `prepare_chapter_plan_request` 准备规划请求参数
2. 校验 prompt_system 和 prompt_user 不能同时为空，否则抛出 `PROMPT_CONFIG_ERROR`
3. 调用 `run_plan_llm_step` 执行规划 LLM 调用
4. 组装返回数据，包含 plan 输出、warnings、parse_error、finish_reason

### 2.2 generate_chapter_precheck 方法

**功能**: 生成预检接口，在不调用 LLM 的情况下预览完整的提示词和配置信息。

**参数**: 同 `generate_chapter`，额外约束 `body.plan_first` 必须为 False。

**流程**:
1. 拒绝 `plan_first` 模式（预检不支持依赖 LLM 产出的 plan）
2. 调用 `prepare_chapter_generate_request` 并设置 `require_api_key=False`
3. 校验渲染日志和提示词
4. 返回预检数据包，包含:
   - `task`: 任务类型 "chapter_generate"
   - `macro_seed`: 宏种子
   - `prompt_system` / `prompt_user`: 系统/用户提示词
   - `messages`: 消息列表
   - `render_log`: 渲染日志
   - `style_resolution`: 风格解析信息
   - `memory_pack` / `memory_injection_config` / `memory_retrieval_log_json`: 记忆相关配置
   - `mcp_research`: MCP 研究结果
   - `prompt_overridden`: 提示词是否被覆盖

### 2.3 run_plan_first_step 方法

**功能**: 在 plan_first 模式下执行规划步骤。

**参数**:
- `prepared`: `PreparedChapterGenerateRequest` 已准备好的请求
- `body`: 原始请求体
- `actor_user_id`: 操作用户 ID

**流程**:
1. 校验规划提示词不为空
2. 调用 `run_plan_llm_step` 执行 LLM 规划调用，优先使用 `plan_llm_call`，回退到通用 `llm_call`
3. 提取规划文本 `plan_text`
4. 若规划文本非空，调用 `inject_plan_into_render_values` 将规划注入渲染值
5. 调用 `render_main_prompt` 重新渲染主提示词（因为渲染值已更新）
6. 返回 `(plan_out, plan_warnings, plan_parse_error)` 三元组

### 2.4 apply_target_word_count 方法

**功能**: 根据目标字数调整 LLM 调用的 `max_tokens` 参数。

**流程**:
- 如果 `body.target_word_count` 为 None，不做任何操作
- 否则调用 `estimate_max_tokens` 估算合适的 max_tokens 值
- 通过 `with_param_overrides` 覆盖 `prepared.llm_call` 的参数

### 2.5 generate_chapter 方法 (核心入口)

**功能**: 非流式章节生成的完整入口。

**参数**: logger, request_id, chapter_id, body, user_id, x_llm_provider, x_llm_api_key

**完整流程**:
1. **准备阶段**: 调用 `prepare_chapter_generate_request`（require_api_key=True），若 render_values 为 None 则抛错
2. **规划阶段**: 如果 `body.plan_first` 为 True，调用 `run_plan_first_step`
3. **长度控制**: 调用 `apply_target_word_count`
4. **LLM 调用**: 调用 `run_chapter_generate_llm_step`，run_type 为 "chapter"
5. **后处理**: 调用 `_append_post_process_steps`（润色和内容优化）
6. **结果组装**:
   - 添加 warnings、parse_error
   - 如果是 plan_first 模式，附加 plan 相关信息
   - 添加 generation_run_id、latency_ms、dropped_params、finish_reason

## 三、准备阶段 (chapter_generation_prepare_service.py)

**文件路径**: `backend/app/services/chapter_generation_prepare_service.py`

此文件负责章节生成请求的全部准备工作。

### 3.1 resolve_task_llm_for_call 方法

**功能**: 解析任务对应的 LLM 配置。

**流程**:
1. 调用 `resolve_task_llm_config` 获取 LLM 配置
2. 如果配置为 None，抛出 `LLM_CONFIG_ERROR`（提示用户在 Prompts 页保存配置）
3. 如果请求头中的 provider 与当前任务 provider 不一致，抛出错误

### 3.2 find_missing_prereq_numbers 方法

**功能**: 查找当前章节之前缺少内容或摘要的前置章节。

**参数**: db, project_id, outline_id, chapter_number

**流程**:
1. 如果 chapter_number <= 1，直接返回空列表
2. 查询当前章节之前的所有章节的 number、content_md、summary
3. 遍历 1 到 chapter_number-1，检查每个章节是否有内容或摘要
4. 返回缺少内容和摘要的章节号列表

### 3.3 _require_chapter_prereqs_if_needed 方法

**功能**: 在顺序生成模式下检查前置章节是否完成。

**流程**:
- 检查 `body_context.require_sequential` 是否为 True
- 如果为 True，调用 `find_missing_prereq_numbers`
- 如果存在缺失，抛出 `CHAPTER_PREREQ_MISSING` 错误

### 3.4 prepare_chapter_generate_request 方法 (核心)

**功能**: 完整的章节生成请求准备流程，返回 `PreparedChapterGenerateRequest`。

**详细流程**:

1. **宏种子解析**: 调用 `resolve_macro_seed`
2. **权限与前置检查**:
   - `require_chapter_editor`: 验证用户对章节的编辑权限
   - `_require_chapter_prereqs_if_needed`: 顺序模式下检查前置章节
3. **LLM 配置解析**:
   - 如果 `require_api_key=True`，调用 `resolve_task_llm_for_call` 获取完整 LLM 配置
   - 如果 `require_api_key=False`（预检模式），仅解析预设信息
4. **上下文构建**: 调用 `build_chapter_generate_render_values` 获取:
   - `values`: 渲染变量字典
   - `base_instruction`: 基础指令文本
   - `requirements_obj`: 需求对象
   - `style_resolution`: 风格解析结果
5. **上下文优化器配置**: 从 ProjectSettings 读取 `context_optimizer_enabled`
6. **记忆注入**: 调用 `prepare_chapter_memory_injection` 准备记忆数据
7. **记忆运行参数**: 调用 `build_memory_run_params_extra_json` 构建额外参数
8. **MCP 研究**:
   - 构建 MCP 研究配置 (`build_mcp_research_config`)
   - 执行 MCP 研究步骤 (`run_mcp_research_step`)
   - 注入 MCP 研究结果到渲染值 (`inject_mcp_research_into_values`)
9. **构建 PreparedChapterGenerateRequest 对象**
10. **规划模式处理** (如果 `body.plan_first`):
    - 解析 plan_chapter 任务的 LLM 配置
    - 确保默认规划预设存在
    - 渲染规划提示词 (`render_preset_for_task` with task="plan_chapter")
    - 设置规划相关字段到 prepared 对象
11. **非规划模式处理**: 直接调用 `render_main_prompt` 渲染主提示词
12. **构建运行参数 JSON**: 调用 `build_run_params_json`

### 3.5 render_main_prompt 方法

**功能**: 渲染主章节生成提示词。

**流程**:
1. 调用 `render_preset_for_task` (task="chapter_generate") 获取渲染后的提示词
2. 保存预检版本的提示词
3. 调用 `apply_prompt_override` 应用用户的提示词覆盖
4. 设置 prepared 对象的所有提示词字段
5. 构建 `prompt_inspector` 参数（包含预检版和最终版的对比信息）
6. 重新构建 `run_params_json`

## 四、计划准备 (chapter_generation_plan_prepare_service.py)

**文件路径**: `backend/app/services/chapter_generation_plan_prepare_service.py`

此文件负责独立的章节规划请求准备。

### 4.1 prepare_chapter_plan_request 方法

**功能**: 准备章节规划请求，返回 `PreparedChapterPlanRequest`。

**详细流程**:

1. **权限验证**: `require_chapter_editor` 验证编辑权限
2. **前置检查**: `_require_chapter_prereqs_if_needed`
3. **LLM 配置解析**: 解析 `plan_chapter` 任务的 LLM 配置
4. **确保默认预设**: `ensure_default_plan_preset`
5. **项目设置加载**: 获取 world_setting、style_guide、constraints
6. **上下文条件过滤**: 根据 body.context 的各 include 标志过滤上下文
7. **角色数据加载**: 根据 character_ids 查询角色并格式化
8. **前章上下文**: `load_previous_chapter_context` 加载前一章内容
9. **构建渲染值字典**:
   - 顶层字段: project_name, genre, logline, world_setting, style_guide 等
   - 嵌套命名空间:
     - `project`: 项目级信息
     - `story`: 故事级信息（大纲、章节号、前章内容等）
     - `user`: 用户指令
   - `context_optimizer_enabled`: 上下文优化器开关
10. **宏种子解析**: 生成种子后缀加 ":plan"
11. **提示词渲染**: `render_preset_for_task` (task="plan_chapter")
12. **返回 PreparedChapterPlanRequest 对象**

## 五、提示词构建 (chapter_generation_prompt_service.py)

**文件路径**: `backend/app/services/chapter_generation_prompt_service.py`

### 5.1 resolve_macro_seed 方法

**功能**: 解析宏种子，用于提示词模板中的随机性控制。

**规则**:
- 如果请求体中有 `macro_seed` 且非空，使用它（截断至 256 字符）
- 否则使用 `request_id` 作为种子

### 5.2 apply_prompt_override 方法

**功能**: 应用用户的提示词覆盖。

**三种模式**:
1. **无覆盖**: 直接返回原始提示词
2. **消息列表覆盖**: 如果 `override.messages` 非空，用 `coalesce_system` 和 `flatten_messages` 重新组织消息
3. **字段覆盖**: 用 `override.system` 和 `override.user` 分别覆盖系统和用户提示词

**返回**: `(prompt_system, prompt_user, prompt_messages, override_applied)` 四元组

### 5.3 _redact_prompt_override_for_params / _redact_prompt_preview_for_params

**功能**: 对提示词内容进行脱敏（redact），用于存储到运行参数中时保护敏感信息。

- `_redact_prompt_override_for_params`: 脱敏 override 中的 system、user 和 messages 内容
- `_redact_prompt_preview_for_params`: 脱敏预览提示词

### 5.4 build_prompt_inspector_params 方法

**功能**: 构建提示词审查参数，记录预检版和最终版的对比信息。

**返回字段**:
- `macro_seed`: 宏种子
- `prompt_overridden`: 是否被覆盖
- `precheck`: 预检版提示词（脱敏后）
- `final`: 最终版提示词（脱敏后）
- `override`: 覆盖配置（脱敏后，可选）

### 5.5 MCP 研究相关方法

**build_mcp_research_config**: 从请求体提取 MCP 研究配置，构建 `McpResearchConfigSvc` 对象。

**inject_mcp_research_into_values**: 将 MCP 研究上下文注入渲染值:
- 在 `instruction` 字段末尾追加「资料收集 - 参考资料」
- 同时更新 `user.instruction`
- 设置 `values["mcp_research"]`

**build_mcp_research_params**: 构建 MCP 研究参数记录。

## 六、流式生成 (chapter_generation_stream_service.py)

**文件路径**: `backend/app/services/chapter_generation_stream_service.py`

### 6.1 常量

- `SSE_BLOCKING_STEP_HEARTBEAT_SECONDS = 1.0`: 阻塞步骤心跳间隔

### 6.2 _chunk_text 方法

**功能**: 将文本按 chunk_size（默认 2048 字符）分割为多段。

### 6.3 prepare_chapter_stream_request 方法

**功能**: 准备流式章节生成请求，基于 `prepare_chapter_generate_request`，并验证渲染值。

### 6.4 generate_chapter_stream_events 方法 (核心生成器)

**功能**: SSE 流式章节生成的核心生成器函数。

**完整流程**:

1. **初始化 SSE**: 发送 `sse_start` 和 `sse_progress(0%)`
2. **规划阶段** (如果 plan_first):
   - 使用 `stream_blocking_call_with_heartbeat` 包装 `run_plan_first_step`
   - 发送规划进度事件 (5%)
   - 如果规划解析失败，发送警告进度事件 (6%)
   - 渲染章节提示词 (8%)
3. **长度控制**: `apply_target_word_count`
4. **LLM 流式调用** (10%):
   - 支持重试机制，最多 `task_llm_max_attempts` 次
   - 每次尝试:
     - 调用 `call_llm_stream_messages` 获取流式迭代器
     - 逐块读取 delta，发送 `sse_chunk`
     - 每 12 个 chunk 发送一次心跳
     - 每 0.8 秒更新一次进度（根据目标字数或默认 12000 字符估算）
   - **流式回退**: 如果流式调用未收到任何分片（chunk_count == 0），回退到非流式调用:
     - 使用 `call_llm_messages` 非流式调用
     - 非流式调用也支持重试
     - 将完整文本按 2048 字符分块发送
   - **指数退避重试**: 使用 `compute_backoff_seconds` 计算退避时间
5. **运行记录**: 调用 `write_generation_run` 记录运行，run_type 为 "chapter_stream"
6. **输出解析** (90%): 使用 `contract_for_task("chapter_generate")` 解析输出
7. **后处理 - 润色** (如果 body.post_edit):
   - 使用 `stream_blocking_call_with_heartbeat` 包装 `run_post_edit_step` (95%)
   - 如果成功应用，替换 content_md
8. **后处理 - 内容优化** (如果 body.content_optimize):
   - 使用 `stream_blocking_call_with_heartbeat` 包装 `run_content_optimize_step` (97%)
   - 如果成功应用，替换 content_md
9. **完成**: 发送 sse_progress(100%), sse_result, sse_done

**错误处理**:
- `GeneratorExit`: 静默返回
- `AppError`: 如果生成已开始但运行记录未写入，先写入错误记录，然后发送 sse_error
- `Exception`: 同上，额外记录异常日志

**重试参数额外记录**:
- `stream_fallback`: 是否使用了非流式回退
- `llm_retry`: 重试尝试记录

## 七、记忆集成 (chapter_generation_memory_service.py)

**文件路径**: `backend/app/services/chapter_generation_memory_service.py`

### 7.1 resolve_memory_modules 方法

**功能**: 解析记忆模块开关配置。

**默认模块配置**:

| 模块名 | 默认值 | 说明 |
|-------|--------|------|
| worldbook | True | 世界书 |
| story_memory | True | 故事记忆 |
| semantic_history | False | 语义历史 |
| foreshadow_open_loops | False | 伏笔/开放环 |
| structured | True | 结构化记忆 |
| tables | True | 表格记忆 |
| vector_rag | True | 向量 RAG |
| graph | True | 图谱 |
| fractal | True | 分形记忆 |

### 7.2 prepare_chapter_memory_injection 方法

**功能**: 准备章节记忆注入。

**流程**:

1. **禁用检查**: 如果 `body.memory_injection_enabled` 为 False，返回空的 `ChapterMemoryPreparation`

2. **查询文本构建**:
   - 如果用户提供了 `memory_query_text`，使用用户提供的（截断至 5000 字符）
   - 否则使用 `base_instruction` 加上 `chapter.plan`（截断至 5000 字符）
   - 记录 `query_text_source`（"user" 或 "auto"）

3. **查询预处理**:
   - 调用 `parse_query_preprocessing_config` 解析预处理配置
   - 调用 `normalize_query_text` 标准化查询文本

4. **记忆检索**:
   - 调用 `retrieve_memory_context_pack` 获取记忆上下文包
   - 如果检索失败，设置 `pack_errors = ["memory_pack_error"]`

5. **记忆注入到渲染值**: 将 `memory_pack` 设置到 `values["memory"]`

6. **构建注入配置**: 包含 query_text、source、modules、原始和标准化查询文本、预处理观测

7. **构建检索日志**: 调用 `build_memory_retrieval_log_json`

### 7.3 build_memory_run_params_extra_json 方法

**功能**: 构建记忆相关的运行参数。

**返回字段**:
- `style_resolution`: 风格解析信息
- `memory_injection_enabled`: 是否启用记忆注入
- `memory_injection_config`: 记忆注入配置（如果启用）
- `memory_retrieval_log_json`: 记忆检索日志（如果启用）

## 八、后处理 (chapter_generation_post_process_service.py)

**文件路径**: `backend/app/services/chapter_generation_post_process_service.py`

### 8.1 _append_post_process_steps 方法

**功能**: 为非流式章节生成结果追加后处理步骤。

**两个后处理步骤**:

#### 8.1.1 润色 (post_edit)

**触发条件**: `body.post_edit == True`

**流程**:
1. 提取当前 `content_md`
2. 如果有内容:
   - 保存原始内容到 `data["post_edit_raw_content_md"]`
   - 调用 `run_post_edit_step`，传入 `post_edit_sanitize` 标志
   - 记录 warnings、parse_error、run_id、edited_content_md
   - 如果 step.applied 为 True，用编辑后的内容替换 content_md
3. 如果无内容:
   - 添加 "post_edit_no_content" 警告

#### 8.1.2 内容优化 (content_optimize)

**触发条件**: `body.content_optimize == True`

**流程**: 与润色类似
1. 提取当前 `content_md`（可能已被润色修改）
2. 调用 `run_content_optimize_step`
3. 如果优化成功，替换 content_md

**注意**: 润色和内容优化是串行执行的，内容优化作用于润色后的内容。

## 九、数据模型 (chapter_generation_models.py)

**文件路径**: `backend/app/services/chapter_generation_models.py`

### 9.1 ChapterMemoryPreparation

记忆准备结果的数据类。

| 字段 | 类型 | 说明 |
|------|------|------|
| memory_pack | dict \| None | 记忆上下文包 |
| memory_injection_config | dict \| None | 记忆注入配置 |
| memory_retrieval_log_json | dict \| None | 记忆检索日志 |

### 9.2 PreparedChapterPlanRequest

章节规划请求的准备结果。

| 字段 | 类型 | 说明 |
|------|------|------|
| project_id | str | 项目 ID |
| resolved_api_key | str | 已解析的 API 密钥 |

## 十六、长度控制 (length_control.py)

**文件路径**: `backend/app/services/length_control.py`

### 16.1 _PROVIDER_MAX_TOKENS 常量

各提供商默认最大 tokens:
- anthropic: 8192
- gemini: 8192
- openai / openai_responses / openai_compatible / openai_responses_compatible: 8192

### 16.2 estimate_max_tokens 方法

**功能**: 根据目标字数估算合适的 max_tokens。

**算法**:
- 如果 `target_word_count <= 0`，返回 1500
- 从 `max_output_tokens_limit` 或默认值获取模型上限 `cap`
- 估算值 = `target_word_count * 1.4 + 512`
- 返回 `max(256, min(cap, estimated))`

**设计意图**: 中文约 1.4 个 token/字，额外加 512 作为格式标记的缓冲。

## 十七、上下文优化器 (context_optimizer.py)

**解析头部格式**: `【世界书条目：Title | Reason | priority:Priority】`

**排序规则**: 按优先级降序（must > important > optional > 其他），相同优先级按标题排序。

### 19.1 _validate_rewrite_output 方法

**功能**: 验证重写输出的质量。

**检查规则**:
1. 如果编辑后内容为空，返回 `{prefix}_no_content`
2. 如果编辑后内容少于 80 字符，返回 `{prefix}_too_short`
3. 如果原文 >= 400 字符且编辑后少于原文 40%，返回 `{prefix}_too_short`

### 20.1 resolve_style_guide 方法

**功能**: 解析生效的风格指南文本。

## 二十一、标注服务 (annotations_service.py)

**文件路径**: `backend/app/services/annotations_service.py`

### 21.1 apply_position_fallback 方法

**功能**: 为标注修复位置信息。当标注的 position/length 无效时，尝试在文本中搜索关键词来定位。

**候选搜索针** (`_candidate_needles`):
1. metadata 中的 keyword、excerpt、needle 字段
2. 标注的 title
3. 标注 content 的前 80 字符

**搜索策略**:
- 精确搜索（最多 80 字符）
- 如果搜索针超过 20 字符且精确搜索失败，尝试前 20 字符搜索
- 找到后更新 position 和 length，并在 metadata 中记录 `position_fallback`
- 最多尝试 `max_attempts`（默认 40）个标注

### 21.2 build_annotations_from_story_memories 方法

**功能**: 从 StoryMemory 列表构建标注列表。

**流程**:
1. 将每个 StoryMemory 转换为标注字典（包含 id, type, title, content, importance, position, length, tags, metadata）
2. 调用 `apply_position_fallback` 修复位置
3. 返回 `(annotations, stats)` 二元组
