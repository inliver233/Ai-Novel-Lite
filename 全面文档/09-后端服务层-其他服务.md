# 09 - 后端服务层：其他服务

## 一、提示词系统服务

### 1.1 提示词模板引擎 (`prompting.py`)

核心模板渲染引擎，支持变量替换、条件分支和宏展开。

#### 1.1.1 模板语法

**变量替换**：
- `{{ variable_name }}`：简单变量替换
- 支持嵌套路径：`{{ parent.child.field }}`（点分隔，支持 dict 和 list 索引）

**条件分支**：
- `{% if variable %}...{% else %}...{% endif %}`
- 安全路径验证：只允许字母开头，不允许下划线开头

**宏系统**（渲染后处理）：
- `{{ date }}`：当前日期
- `{{ time }}`：当前时间
- `{{ isodate }}`：ISO 格式日期
- `{{ random::A::B }}`：随机选择（非确定性）
- `{{ pick::A::B }}`：确定性选择（基于 seed）
- `{{ // comment }}`：注释（渲染时移除）

#### 1.1.2 关键函数

- **`render_template(template, values, *, macro_seed)`**：
  - 返回 `(rendered_text, missing_variables, error)`
  - 先转义宏标记 → 变量替换 → 条件处理 → 恢复宏 → 执行宏

- **`_is_safe_path(path)`**：验证路径安全性
- **`_try_resolve_path(values, path)`**：解析嵌套路径
- **`_escape_macros()` / `_restore_macros()`**：宏转义/恢复
- **`_evaluate_macros(text, *, seed)`**：宏执行

### 1.2 提示词存储 (`prompt_store.py`)

角色信息格式化工具。

- **`format_characters(chars)`**：将角色列表格式化为 Markdown
  - 格式：`- 角色名（角色）`
  - 子项：档案、备注

### 1.3 提示词预设服务 (`prompt_presets.py`)

管理提示词预设（Prompt Preset）的创建、渲染和缓存。

#### 1.3.1 预设默认名称

| 预设 | 名称常量 |
|------|---------|
| 章节规划 | `DEFAULT_PLAN_PRESET_NAME` |
| 后处理 | `DEFAULT_POST_EDIT_PRESET_NAME` |
| 内容优化 | `DEFAULT_CONTENT_OPTIMIZE_PRESET_NAME` |

#### 1.3.2 渲染缓存

- LRU 缓存，最多 512 条
- 基于模板内容和变量的 SHA256 哈希作为缓存 key
- 支持 TTL 过期

#### 1.3.3 核心函数

- **`parse_json_list(raw)` / `parse_json_dict(raw)`**：安全 JSON 解析
- **`_prompt_block_from_resource(preset_id, block_resource)`**：从资源定义创建 PromptBlock ORM 对象
- **`_ensure_default_preset_from_resource(db, project_id, resource_key, activate)`**：确保默认预设存在
- **`render_preset_for_task(db, project_id, task, values, macro_seed, provider)`**：
  - 渲染指定任务的完整提示词
  - 返回 `(system, user, messages, budget_info, context_optimizer_info, warnings, render_log)`
  - 支持 ContextOptimizer 上下文优化
  - 支持 max_context_tokens 限制

### 1.4 提示词预设资源 (`prompt_preset_resources.py`)

管理内置提示词预设资源文件（JSON + 模板文件）。

#### 1.4.1 数据结构

## 二、LLM 服务层

### 2.1 合约服务 (`llm_contract_service.py`)

LLM provider/model 的合规验证和能力查询。

#### 合约模式

- **`audit`**（默认）：审计模式，宽松检查
- **`enforce`**：强制模式，严格合规

#### 方法详解

- **`current_contract_mode()`**：从配置读取当前模式
- **`resolve_provider_model(provider, model, *, mode)`**：解析并验证 provider/model 组合
- **`normalize_provider_model()`**：标准化 provider/model 名称
- **`normalize_base_url_for_provider()`**：标准化 base_url
- **`normalize_max_tokens_for_provider()`**：
  - 无值时返回推荐值
  - 有值时钳制到 output_tokens_limit
- **`contract_metadata(provider, model)`**：
  - 返回完整合约元数据：provider/model/pricing/compatibility_alias/notes
- **`capability_contract(provider, model)`**：
  - 返回能力合约：max_tokens_limit / max_tokens_recommended / context_window_limit

#### 错误码映射

| 合约码 | 中文消息 |
|--------|---------|
| provider_required | provider 不能为空 |
| unsupported_provider | 不支持的 provider |
| model_required | model 不能为空 |
| unsupported_model | 未注册的官方模型 |
| base_url_required | 必须填写 base_url |
| invalid_base_url_scheme | base_url 必须以 http(s):// 开头 |

### 2.2 密钥解析器 (`llm_key_resolver.py`)

API 密钥解析服务，支持多级优先级。

#### 解析优先级

1. 请求头 `X-LLM-Api-Key`
2. LLMProfile 中存储的加密密钥
3. 项目关联的 LLMProfile

#### 方法详解

- **`normalize_header_api_key(value)`**：标准化请求头密钥
- **`resolve_api_key_for_project(db, *, project, user_id, header_api_key)`**：项目级解析
- **`resolve_api_key_for_profile(*, profile, header_api_key)`**：配置文件级解析
  - 使用 `decrypt_secret()` 解密密文
  - 密钥解密失败提示用户重新保存
- **`resolve_api_key(db, *, user_id, header_api_key, project, profile)`**：通用入口

### 2.3 LLM 配置模板 (`llm_profile_template.py`)

LLM 参数模板工具。

- **`decode_stop_json(raw)` / `encode_stop_json(stop)`**：stop 序列的编解码
- **`decode_extra_json(raw)` / `encode_extra_json(extra)`**：额外参数编解码
- **`llm_contract_meta(provider, model)`**：获取合约元数据
- **`apply_profile_template_to_llm_row(*, row, profile)`**：
  - 将 LLMProfile 的所有参数（provider/model/base_url/temperature/top_p/max_tokens/penalties/stop/timeout/extra）应用到目标行

### 2.4 LLM 重试服务 (`llm_retry.py`)

LLM 调用的重试、退避和错误处理。

#### 配置（环境变量）

| 环境变量 | 默认值 | 范围 |
|---------|--------|------|
| TASK_LLM_MAX_ATTEMPTS | 3 | [1, 10] |
| TASK_LLM_RETRY_BASE_SECONDS | 0.8 | [0.0, 60.0] |
| TASK_LLM_RETRY_MAX_SECONDS | 8.0 | [0.0, 300.0] |
| TASK_LLM_RETRY_JITTER | 0.2 | [0.0, 1.0] |

#### 可重试错误判定

**`is_retryable_llm_error(exc)`**：
- AppError code: LLM_TIMEOUT / LLM_UPSTREAM_ERROR / LLM_RATE_LIMIT
- HTTP status: 408 / 429 / 500 / 502 / 503 / 504
- TimeoutError

#### 退避计算

**`compute_backoff_seconds()`**：
- 指数退避：`base * 2^(attempt-2)`
- 速率限制加倍：`raw * 2.0`
- 抖动：`raw * (1 + uniform(-jitter, jitter))`

#### `call_llm_and_record_with_retries()`

带重试的 LLM 调用：
- 每次重试生成唯一 request_id
- 支持 per-attempt 的 LLM 参数覆盖
- 支持重试时替换 system prompt 或追加 system instruction
- 失败时抛出 `LlmRetryExhausted`（含所有尝试记录）

## 三、认证服务 (`auth_service.py`)

#### 方法详解

- **`hash_password(password)`**：

  - bcrypt 验证，异常时返回 False

- **`ensure_admin_user(db)`**：
  - 从配置读取管理员信息
  - 自动创建/更新管理员用户和密码
  - 设置 `is_admin=True`

## 五、搜索索引服务 (`search_index_service.py`)

全文搜索索引管理服务，支持 SQLite FTS5。

### 5.1 数据模型

```python
@dataclass(frozen=True, slots=True)
class SearchDocInput:
    source_type: str      # chapter / character / outline / worldbook / entity / ...
    source_id: str
    title: str
    content: str
    url_path: str | None
    locator_json: str | None
```

### 5.2 FTS 操作

- **`_fts_enabled(db)`**：检查 `search_index` FTS 表是否存在
- **`_fts_delete(db, *, rowid, title, content)`**：FTS 删除（外部内容同步模式）
- **`_fts_insert(db, *, rowid, title, content)`**：FTS 插入

### 5.3 索引构建

- 从多种来源收集文档：章节、角色、大纲、世界书、结构化记忆（实体/关系/证据）、故事记忆、导入文档、数值表行
- 每种来源的 title 限 400 字符，content 限 6000 字符
- `schedule_search_rebuild_task()`：调度后台重建任务

### 5.4 搜索查询

- 最多 8 个查询词
- 支持 FTS5 全文搜索和 LIKE 回退
- 安全过滤查询词（只允许字母数字下划线）

`queued` / `running` / `paused` / `failed` / `done` / `succeeded` / `canceled`

#### 方法详解

- **`project_task_to_dict(task)`**：序列化为字典
- **`list_project_tasks()`**：分页查询（支持状态过滤、时间游标）
- **`run_project_task(task_id)`**：执行任务分发器
- 任务计时：创建时间 / 启动时间 / 心跳时间 / 完成时间
- 错误信息自动脱敏

### 11.2 项目任务事件服务 (`project_task_event_service.py`)

任务事件流管理。

#### 方法详解

- **`project_task_event_task_payload(task)`**：构建事件载荷（含 id/project_id/kind/status/timings/error）
- **`append_project_task_event(db, *, task, event_type, payload, source)`**：追加事件记录（自动脱敏）
- **`reset_project_task_to_queued(*, task, increment_retry_count)`**：重置任务为排队状态
- **`mark_project_task_enqueue_failed(db, *, task, exc, logger, request_id)`**：标记入队失败
- **`emit_and_enqueue_project_task(db, *, task, request_id, logger, event_type, source, payload)`**：
  - 先追加事件 → 再入队任务队列
  - 入队失败自动标记 failed

- **`list_project_task_events_after(db, *, project_id, after_seq, limit)`**：查询事件流（顺序递增）
- **`latest_project_task_event_seq(db, *, project_id)`**：获取最新事件序列号
- **`build_project_task_active_snapshot(db, *, project_id, limit)`**：构建活跃任务快照
- **`project_task_event_to_dict(event)`**：事件序列化

### 11.3 项目任务运行时服务 (`project_task_runtime_service.py`)

任务运行时心跳和看门狗机制。

#### 心跳机制

- **`touch_project_task_heartbeat(*, task_id)`**：更新心跳时间戳
- **`start_project_task_heartbeat(*, task_id)`**：启动后台心跳线程
  - 间隔：`project_task_heartbeat_interval_seconds`（默认 5 秒）
- **`stop_project_task_heartbeat(handle)`**：停止心跳

#### 看门狗机制

- 检测 running 但心跳超时的任务
  - 超时阈值：`project_task_stale_running_timeout_seconds`（默认 120 秒）
- 检测 queued 但队列中不存在的任务
  - 和解阈值：`project_task_queued_reconcile_after_seconds`（默认 20 秒）

### 11.4 项目任务运行时视图服务 (`project_task_runtime_view_service.py`)

任务运行时数据视图化。

- **`_batch_task_to_dict(task)`**：批量生成任务序列化
- **`_batch_item_to_dict(item)`**：批量任务项序列化（含 attempt_count、last_request_id、error 等）
- **`_normalize_step(step)`**：标准化步骤数据

## 十四、任务队列 (`task_queue.py`)

后台任务队列抽象层，支持 RQ（Redis Queue）和 Inline 两种后端。

### 14.1 任务类型

```python
TaskKind = Literal["batch_generation", "memory_task", "import_task", "project_task"]
```

### 14.2 InlineTaskQueue

开发/测试用进程内线程 worker：
- 可配并发数（`INLINE_WORKER_CONCURRENCY`，默认按 CPU 核数，最多 8）
- 守护线程执行
- 支持 `has_task()` 查询

### 14.3 RqTaskQueue

生产用 Redis Queue：
- 任务超时 1 小时
- 结果/失败 TTL 7 天
- 支持队列状态检查

### 14.4 自动回退机制

非生产环境（`app_env != "prod"`）：
1. Redis 不可达 → 自动回退 Inline
2. Redis 可达但无 worker → 自动回退 Inline
3. 显式设置 `TASK_QUEUE_BACKEND=rq` 时不回退

### 14.5 健康检查

**`get_queue_status_for_health()`**：
- Redis ping 状态（2 秒 TTL 缓存）
- RQ worker/queue 状态检查
- 安全：不泄露 redis_url
- 返回 effective_backend、worker_hint 等

### 16.1 输出合约 (`output_contracts.py`)

多种输出格式的解析器集合。

#### 通用 JSON 提取

  - 先尝试 `\`\`\`json...\`\`\`` 代码块

#### 大纲解析

**`parse_outline_output(text)`**：

- finish_reason=length 时添加截断警告

## 十七、MCP 服务 (`mcp/service.py`)

Model Context Protocol 工具调用服务。

### 17.1 数据结构

```python
@dataclass
class McpToolSpec:        # 工具规格
    name: str
    description: str
    args_schema: dict

@dataclass
class McpToolCall:        # 工具调用请求
    tool_name: str
    args: dict

@dataclass
class McpToolCallResult:  # 调用结果
    run_id: str
    tool_name: str
    ok: bool
    output_text: str
    error_code: str | None
    error_message: str | None
    latency_ms: int
    truncated: bool

@dataclass
class McpResearchConfig:  # 研究配置
    enabled: bool
    allowlist: list[str]
    calls: list[McpToolCall]
    timeout_seconds: float | None
    max_output_chars: int | None
```

### 17.2 内置 Mock 工具

| 工具名 | 功能 |
|--------|------|
| mock.echo | 回显 args.text |
| mock.sleep | 休眠 args.seconds 秒 |
| mock.fail | 抛出异常（失败测试） |

### 17.3 核心方法

- **`list_mcp_tools()`**：列出所有可用工具
- **`run_mcp_tool_call_and_record()`**：
  - 验证 allowlist
  - 带超时执行（默认 6 秒）
  - 输出长度限制（默认 6000 字符）
  - 自动脱敏和截断
  - 记录 GenerationRun（type=mcp_tool）
  - 错误码：ALLOWLIST_REQUIRED / TOOL_NOT_FOUND / TOOL_NOT_ALLOWED / TOOL_TIMEOUT / TOOL_ERROR

- **`replay_mcp_tool_call_and_record()`**：重放已记录的工具调用

- **`run_mcp_research_and_record()`**：
  - 批量执行工具调用（最多 6 个）
  - 汇总输出为 `【工具名】\n输出` 格式
  - 返回 (context_text, results, warnings)

### 17.4 `mcp/__init__.py`

模块导出：
- `McpResearchConfig`、`McpToolCall`、`McpToolCallResult`、`McpToolSpec`
- `list_mcp_tools`、`run_mcp_tool_call_and_record`、`replay_mcp_tool_call_and_record`、`run_mcp_research_and_record`
