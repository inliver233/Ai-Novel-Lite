# ainovel MVP (Atelier) -- 项目总览

## 1. 项目名称与定位

**项目名称**: ainovel MVP (Atelier)

**项目定位**: 一个面向 AI 辅助长篇小说创作的全栈 Web 平台。该平台整合了多种大语言模型 (LLM) 服务商，为小说创作者提供从项目规划、大纲生成、章节撰写、到记忆管理和导出的一站式写作体验。系统支持多用户、多项目管理，具备完善的长期记忆系统（包括世界书、结构化记忆、向量 RAG、知识图谱、分形记忆等），可将创作上下文持续注入 AI 生成过程，从而保持长篇小说的连贯性和一致性。

## 3. 整体架构设计

### 3.1 系统架构概述

本项目采用**前后端分离**的 SPA (Single Page Application) 架构：

```
用户浏览器
    |
    v
[Nginx / Vite Dev Server]  <-- 前端静态资源服务 + API 反向代理
    |
    |-- /api/* --> [FastAPI 后端 (Uvicorn)]  <-- REST API + SSE 流式
    |                    |
    |                    |-- [SQLAlchemy ORM] --> [PostgreSQL / SQLite]
    |                    |
    |                    |-- [httpx] --> [LLM 上游 API]
    |                    |               (OpenAI / Anthropic / Gemini / 兼容 API)
    |                    |
    |                    |-- [RQ] --> [Redis] --> [RQ Worker]
    |                    |               (异步任务: RAG、世界书、批量生成等)
    |                    |
    |                    |-- [Chroma / pgvector] <-- 向量存储 (RAG)
    |
    |-- /* --> 静态 SPA 资源 (React + Vite 构建产物)
```

### 3.2 前后端通信

- **协议**: HTTP/HTTPS REST API，统一前缀 `/api`
- **流式输出**: SSE (Server-Sent Events)，用于 LLM 文本流式生成
- **认证**: Cookie-based Session（支持 dev fallback 免登录模式）
- **请求追踪**: 每个请求分配 `X-Request-Id`，贯穿前后端日志
- **CORS**: 可配置跨域策略，开发环境默认允许 `http://localhost:5173`

### 3.3 数据流向

1. **用户操作** --> 前端 React 组件 --> API 调用 (apiClient.ts)
2. **API 请求** --> Nginx 反向代理 --> FastAPI 路由 --> Service 层
3. **同步操作**: Service --> SQLAlchemy ORM --> 数据库 --> 返回 JSON
4. **异步任务**: Service --> RQ 入队 --> Redis --> RQ Worker 消费 --> 数据库
5. **AI 生成**: Service --> LLM Client (httpx) --> 上游 API --> SSE 流式返回
6. **记忆注入**: 生成前收集 worldbook/story_memory/structured/vector_rag/graph/fractal --> 注入 prompt --> 发送 LLM

### 3.4 分层架构（后端）

```
Routes (app/api/routes/)     -- HTTP 入口，请求/响应处理
    |
Schemas (app/schemas/)       -- Pydantic 数据验证与序列化模型
    |
Services (app/services/)     -- 业务逻辑核心层
    |
Models (app/models/)         -- SQLAlchemy ORM 模型
    |
DB (app/db/)                 -- 数据库会话与迁移管理
    |
LLM (app/llm/)              -- LLM 适配层 (多 Provider 统一接口)
    |
Core (app/core/)            -- 配置、认证、加密、日志等基础设施
```

## 5. 部署架构

### 5.1 Docker Compose 服务组成

项目通过 `docker-compose.yml` 编排 5 个服务：

| 服务 | 镜像 / 构建 | 端口 | 说明 |
|------|-------------|------|------|
| **postgres** | `pgvector/pgvector:pg16` | 5432 (仅本地) | PostgreSQL 16 + pgvector 向量扩展 |
| **redis** | `redis:7-alpine` | 6379 (仅本地) | 消息代理，RQ 任务队列后端 |
| **backend** | 从 `./backend` 构建 | 8000 | FastAPI 应用服务 |
| **rq_worker** | 从 `./backend` 构建 | - | RQ 后台任务 Worker |
| **frontend** | 从 `./frontend` 构建 | 5173:80 | Nginx 静态服务 + API 反向代理 |

### 5.2 服务依赖关系

```
postgres (健康检查) ----+
                        |--> backend (健康检查) --> rq_worker
redis    (健康检查) ----+                    |
                                             +--> frontend
```

### 5.3 数据持久化

| 卷名 | 挂载点 | 内容 |
|------|--------|------|
| `postgres_data` | /var/lib/postgresql/data | PostgreSQL 数据文件 |
| `app_data` | /data | 应用数据（含 `/data/chroma` 向量库和 `/data/secrets` 自动生成的密钥） |

### 5.4 生产部署配置 (docker-compose.prod.yml)

生产环境 overlay 配置会：
- 关闭 Postgres 和 Redis 的外部端口暴露
- 强制 `APP_ENV=prod`
- 禁用 `AUTH_DEV_FALLBACK_USER_ID`
- 要求必须设置 `CORS_ORIGINS`、`AUTH_ADMIN_PASSWORD`、`SECRET_ENCRYPTION_KEY`、`AUTH_SESSION_SIGNING_KEY`
- 后端端口绑定到 `127.0.0.1`（仅本地访问，需通过反向代理对外）

### 5.5 前端容器构建

前端采用两阶段构建：
1. **构建阶段**: Node.js 20 Alpine 环境下执行 `npm ci && npm run build`
2. **运行阶段**: Nginx 1.27 Alpine 提供静态文件服务，同时配置 `/api/` 反向代理到后端

### 5.6 后端容器构建

- 基础镜像: `python:3.11-slim`
- 以非 root 用户 `app` 运行
- 安装锁定依赖 (`requirements.lock.txt`)
- 入口脚本: `scripts/entrypoint.sh`（负责等待数据库就绪、自动生成密钥、执行迁移等）
- 暴露端口: 8000
